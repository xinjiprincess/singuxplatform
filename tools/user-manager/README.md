版本：0.1.9。Windows x64 便携客户端，独立于平台网页及 Docker 运行。

- 身份冲突继续通过 0.1.8 审核流程处理，更新时缺失的联系方式沿用旧账号字段。不生成猜测的学生邮箱或虚构手机号；仍无联系方式的新账号需手动补充。

## 0.1.8 冲突身份审核

- 启动 `release/0.1.8/SinguX-User-Manager-win32-x64/SinguX-User-Manager.exe`，进入任务中心，选择批次和冲突账号，点击“查询并审核身份”。
- 对照报名资料与旧账号，填写核实依据、原用户 ID，并勾选已确认同一人。仅唯一命中的启用 User 可审核；多人命中、管理员、停用、已发出未知写入不会放行。
- 保存审核仅写入本机加密配置，不修改服务器。然后点击该行“核对该账号”并确认，执行资料更新及密码重置，保留原 ID、UID 和历史关联。用户名和初始密码仍为学校代号加学号。
- 绑定按环境及凭据隔离，记录审核时间、依据、原账号快照。以后相同名单可复用；环境、名单或账号资料变化会要求重新核实。绑定及审核记录不会随“清除本机历史”删除。
- 无需服务器升级。不自动删除或合并账号。不把未知密码重置响应视为成功。

## 0.1.7 已迁移账号匹配修复

启动 `release/0.1.7/SinguX-User-Manager-win32-x64/SinguX-User-Manager.exe`。重新选择名单、预览并创建任务，不复用旧任务的目标快照。

已改为目标登录名的普通账号，即使 UID 保留邮箱注册时的值，也可在姓名、至少一项联系方式一致且唯一命中时进入更新确认。仅邮箱相同、多个账号命中、管理员或停用账号仍需人工核实。本修复无需服务器升级，沿用现有用户查询和更新接口。

注意：“更新已有普通账号并重置密码”仍会改密，不是只检查或跳过。请仅选择需要处理的记录。结果待核对的记录不可直接重建任务重复写入；导出完成状态不代表已验证当前密码可登录。

## 本版默认规则

- 用户名默认是表格中的工号/学号，保留前导零，不加 `stu_` 前缀。初始密码默认是本人手机号；缺学工号或手机号时需补全后导入，不生成虚假数据。也可显式选择原来的表格账号/前缀规则及随机密码。
- 手机号是弱口令，请及时通知用户改密；本版不宣称服务器已经实现强制首次改密。已有账号不改名、不重置密码；0.1.0 的历史任务保持其原有随机密码规则，不因升级改变。
- 用户已确认线上继续保持单租户。环境类型选择「单租户平台」后不需要租户 ID，也不会请求企业成员接口；如果响应混入多个不同租户仍会停止。已有配置不擅自改范围，请手动编辑确认。
- **旧后端禁止纯数字用户名。** 必须先部署经过验证的数字学工号兼容补丁，再正式导入。仅更新此客户端并不能解除服务器限制，也不表示服务器已更新。
- 本版发布目录为 `release/0.1.1/SinguX-User-Manager-win32-x64`，旧包保留。退出旧版后运行新 EXE，原加密 Key 配置保留。

## 启动

发布目录中的 `SinguX-User-Manager.exe` 可直接运行。请保留 exe 同目录下的所有文件，不要仅复制 exe。本版本未做代码签名，没有后台服务或自动更新。

源代码运行：在此目录执行 `npm ci`、`npm run build`、`npm start`。Windows 便携包使用 `npm run package` 构建。国内下载可设置 `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/`。

## 首次配置

1. 打开「环境配置」，核对 HTTPS 地址及平台类型。新配置默认预填单租户 `https://www.ciyuancenter.cc`，环境名标记服务器 `43.136.175.19`。只有选择多租户时才填写**账号所属租户 ID**。
2. 打开「API Key 管理」，添加拥有用户管理接口权限的平台 API Key，并关联环境。可保存多组 Key，独立命名、启停、编辑和选择。SSH 的 root 用户及密码不是 API Key，客户端不提供 SSH 或保存 root 密码。
3. 如果需要 AI 列映射建议，另加模型类型的 Key，填写 DeepSeek 或 OpenAI 兼容服务的 Base URL、模型标识和密钥。平台 Key 与模型 Key 不混用。单个导入任务固定绑定一个平台 Key，认证或限额失败会暂停，不轮换 Key 绕过限额。
4. 比赛/企业成员资格与账号创建是两件事。需要额外入企时填写「额外加入的企业 / 比赛租户 ID」；执行前会检查成员接口。该接口可能需要比开放 API Key 更高的权限，若不支持会停止，不会假装加入成功。

## 导入流程

- 选择表格或目录，可递归扫描子目录；只读取 `.xls`、`.xlsx`、`.csv`，跳过隐藏目录、链接、临时文件及其他类型。
- 用户提供的报名模板使用固定解析规则，分别识别报名人、成员和可选指导教师；普通表格自动匹配表头，也可手动改列映射。**不会把团队行、表头或说明行当作用户。**
- 输入稳定的学校/单位代号，再生成预览。学号 `00001` 默认生成 `00001` 登录名，以及类似 `cdut:person:00001` 的内部 uid；单位代号不代表创建企业。选择表格账号/前缀模式时才使用自定义前缀或邮箱/电话派生标识。不同单位若存在同学号会冲突，需人工处理，不能自动覆盖。
- 同一身份所有导入字段完全一致才合并，保留来源行；不同内容保留为冲突行，需人工核对。缺少联系方式、格式错误及科学计数法学工号会阻止提交。原表中已经丢失的前导零无法恢复。
- 默认按所给接口文档同时要求手机号与邮箱。只有确认目标服务器接受单项联系方式后，才关闭该选项。禁止编造缺失邮箱或电话。
- 选中合格人员后「检查连接」，再「确认并导入」。系统原生确认框再次显示目标地址、范围、Key、人数及密码规则。创建角色固定为普通 `User`。默认本人手机号密码，选择随机模式时才生成随机口令。
- 已存在且 uid、用户名、联系方式一致的账号跳过；身份不一致则报冲突，不覆盖旧密码、角色或资料。比赛成员关系只新增 `MEMBER`，不更改既有成员角色或恢复被禁用成员。
- 任务中心可以暂停、核对后恢复、导出结果和单独导出已确认创建的账号口令。口令文件是明文，导出时单独确认，需受控发放并及时删除。服务端是否强制首次改密尚未验证。

## DeepSeek 辅助识别

模型只辅助**表头字段映射**，不负责执行导入，也不自动决定租户、角色或密码。调用前显示提供方域名及待发送字段名，用户确认后才发送；没有数据行、电话、邮箱名单或完整工作簿上传。模型返回仅接受白名单字段及有效、不重复的列号，建议需人工确认。

已知报名模板完全离线识别，无需模型。图片、PDF、Word、任意目录中的非表格材料以及 OCR 不在本版范围内；AI 不会凭空补全学号或联系方式。

## 安全与恢复

- 密钥、任务记录和初始口令通过 Electron `safeStorage` 使用 Windows 用户级加密保存，存储为应用 userData 目录下的 `manager.enc`。不开启明文回退；解密失败会停止而非覆盖旧数据。加密文件不保证能在另一 Windows 账号或机器上恢复。
- 窗口启用 sandbox、contextIsolation，禁用 Node 集成、页面网络请求、外部导航和弹窗；所有网络和文件操作经受限主进程 IPC。模型内容与表格内容均不执行为代码。
- 远端默认要求 HTTPS；显式允许 HTTP 会暴露凭据和用户资料。HTTPS 证书错误不绕过。密钥不会因编辑环境而悄悄发送到另一个地址。
- 新增请求发出前先落盘；超时、程序中断或异常响应不会盲目重试 POST。恢复时重新查询用户列表核对，仍无法确认则保持暂停，需要管理员检查目标平台。
- 已确认建号但成员关系失败时，恢复仅重试成员关系。不能自动回滚整个批次，也不删除生产账号。
- 客户端无法替代服务端幂等约束、权限和租户隔离。并发客户端仍须依赖后端唯一约束；用户列表发生变化时可能要求重新核对。

## 限制与兼容

- 单文件 10 MB，单表一万行、80 列，每次目录最多 200 文件、10 层，预览最多两万人；压缩表格有大小及条目数预检查，解析在限时独立线程执行。
- 当前接口适配要求成功码 `0000`，用户列表为 `data.records` 和 `data.total`。多租户模式要求明确的 `tenantId`，空列表无法核实租户时阻止导入；单租户模式允许旧接口不返回 tenantId 及空列表。最多检查一万名现有用户。无损大整数 ID 应由后端以字符串返回。
- 使用 `POST /api/v1/system/user/list` 和 `POST /api/v1/system/user/add`；可选成员接口为 `GET /api/platform/tenants/{id}/members` 与 `PUT /api/platform/tenants/{id}/members/{userId}`。
- 团队、赛道、院系、年级及源行信息保留在本地记录；现有用户新增接口没有这些字段，不宣称已写入服务器或已建立参赛团队。
- 当前不是通用后台管理器，不支持用户删除、改密、服务器维护，也未内置平台网页。本版的解析、校验和队列模块可供后续网页集成，但尚未完成集成。

## 验证

`npm test` 运行独立单元测试。`tests/electron-smoke.cjs` 使用临时 Windows 加密目录、虚构表格和本机模拟 HTTP API 测试窗口与建号流程，需通过 `PLAYWRIGHT_MODULE` 指定 Playwright 模块路径。真实报名表可用 `node tests/inspect-template.cjs "文件路径"` 离线检查，该脚本只输出计数，不打印个人资料。

本轮未使用 SSH、未调用生产建号接口、未向模型发送真实人员资料。正式导入仍需有效平台 API Key、准确租户 ID，以及目标服务器权限与接口兼容性验证。

# 0.1.5 单账号错误隔离

启动 `release/0.1.5/SinguX-User-Manager-win32-x64/SinguX-User-Manager.exe`，先退出旧客户端。

单个账号错误不影响后面的账号，任务中心可逐行“核对该账号”。“未成功账号 Excel”导出当前快照，包含未提交、失败、冲突、结果待核对等状态和原始来源，不包含已成功或已确认存在的账号，不含密码。导出表包含联系方式，请妥善保管。

结果待核对可能是服务端已写入但响应丢失，不能直接当作失败重新导入。普通字段错误可在原表修正后生成新预览；未知结果先核对平台账号。鉴权、限流、列表读取和本地保存错误仍暂停整批。
# 0.1.6 已有账号更新

程序路径：`release/0.1.6/SinguX-User-Manager-win32-x64/SinguX-User-Manager.exe`。先退出旧版，重新添加表格和生成任务；历史任务不自动改变策略。

默认用户名和初始密码均为“学校代号+学号”，例如 `cdut00001`；角色固定 User。默认勾选“更新已有普通账号并重置密码”，取消后保留旧的只新增行为。提交前读取用户列表，列出新增、跳过、改名和密码重置计划，经原生确认框确认后才写入。

旧 UID 为原始学号时，还要求姓名和至少一项联系方式一致。新带学校前缀的 UID 可直接作为强匹配，其他联系方式不能指向另一账号。管理员、停用用户、身份不明、多重匹配或确认后资料发生变化均不会自动更新。若这些检查仍报冲突，请先核对资料，不强制覆盖。

更新通过 `/api/v1/system/user/{id}/update`，提交前后通过 `/api/v1/system/user/detail?id=...` 核对。接口不支持修改 UID，因此保留原 UID。未知更新结果不自动重发，不能凭公开资料回读推断密码；只有更新返回成功且资料回读匹配，才在密码表记录本次重置密码。

更新模式全局间隔至少 500ms（默认 3 并发），以容纳每人两次详情查询。单纯新增模式仍可用 250ms。全部成功更新的记录显示“更新完成”，不会进入未成功 Excel。单账号错误仍不影响其余记录。

本轮仅以模拟数据测试改名/改密。服务器已经存在 update/detail 管理员授权，未重复添加或改变其额度；详情只读检查成功，没有重置生产用户密码。
# v0.1.11 用户查询和批量角色更新

在「用户查询 / 角色更新」选择目标平台管理员 Key，可按 ID、UID、登录名、邮箱或手机号查询详情，编辑资料与角色，或单独重置密码。

批量角色更新：导入 Excel/CSV，选择工作表及表头行，映射用户标识和姓名；未映射目标角色列时使用统一角色。查询全部生成预览后，可执行全部已匹配用户或所选记录。角色只能为 User/Admin；此接口不管理学校、企业或自定义分组。姓名不一致、标识冲突及重复账号跳过并保留原因。

批量更新仅修改 role。支持暂停、再次点击执行继续、完整结果及未成功 Excel 导出。未知写入会先查询核对；当前角色仍未达到目标时须重新导入查询确认。请求没有修改生产数据，实际操作由使用者在客户端提交。
