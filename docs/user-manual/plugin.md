# 智能体平台 · 插件系统介绍

> 更新：2026-10-04。本章为功能与操作参考，实际菜单取决于服务器授权和环境配置。界面存在不表示生产能力已验收，环境边界以项目操作指南为准。

> 插件（Plugin）是智能体平台 中为智能体（Agent）扩展工具能力的关键模块。本文档完整介绍插件的作用，以及创建插件的两条路径：**一般创建插件的方式**（HTTP 接口 / 云端代码）与 3.0 新增的 **Vibe Coding 方式**。

* * *

## 一、什么是插件？为什么需要插件？

插件可以为智能体（Agent）扩展工具能力。**智能体本身是个"大脑"，很聪明，但手是空的。** 你想让它干活，就得给它"手"，插件就是这只手——装上什么，就能做什么。

原生智能体只具备"对话"这一项基本能力，要让它真正"干活"，就需要通过插件为它装上各种工具。常见的插件能力包括：

| 能力 | 说明 | 典型场景 |
| --- | --- | --- |
| 🔎 **网络搜索** | 让智能体联网检索信息 | 获取实时数据、最新资讯 |
| 🗄️ **访问数据库** | 查询、读写企业数据 | 让智能体掌握业务真实情况 |
| 🖼️ **图像处理** | 识别、分析、处理图片 | 扩展视觉理解能力 |

-   没有插件：智能体只能聊天，无法查实时数据、无法读数据库、无法处理图片；
-   装了插件：智能体可以联网、查数据、处理图片，真正成为能解决问题的生产力工具。

> **一句话理解：插件就是智能体的"工具箱"，装什么工具，智能体就能干什么活儿。工具装得越全，这个智能体就越能干。**

智能体平台平台插件支持现有的 API 无缝接入，同时支持 Python、JavaScript 云端代码编写，实时发布，让数据处理得心应手。

## 二、一般创建插件的方式

一般创建插件的方式，核心在于「**创建 → 配置 → 试运行 → 发布**」的标准流程。首先从选择创建方式开始。

### 2.1 两种创建方式

进入「插件」模块，点击「新建插件」，平台支持两种创建方式：

#### 2.1.1 基于已有服务（HTTP 接口）创建

适合**已经有现成接口**的场景。例如企业已有天气查询 API、订单查询接口，或使用了某个第三方服务。

-   只需填写接口地址，即可接入；
-   **无需编程**，零代码成本。

#### 2.1.2 基于云端代码（Node.js / Python）创建

适合**没有现成接口、需要自己写逻辑**的场景。

-   使用 Node.js 或 Python 编写逻辑；
-   支持 **AI 辅助代码生成**。

#### 如何选择？

> 🎯 **一句话：有现成接口 → 用 HTTP；需要新逻辑 → 写代码。**

### 2.2 HTTP 插件配置

创建 HTTP 插件，需要填写 HTTP 接口的 URL，以及 HTTP 接口的请求参数。整个配置过程只需三步：

| 步骤 | 操作 | 说明 |
| --- | --- | --- |
| **1** | 填写接口 URL | 输入 HTTP 接口的完整地址 |
| **2** | 配置请求参数 | 定义入参：Path / Query / Header / Body 四种类型 |
| **3** | 点击「自动解析」 | 系统自动解析接口返回的数据结构，**自动补齐出参** |

> ✨ **小技巧：「自动解析」非常好用**——你连出参都不用手动定义，系统会自动补全。

**HTTP 插件 = 你出接口，平台负责对接**，全程不用写一行代码。

### 2.3 代码插件配置

代码插件配置包含两个页签：**元数据** 与 **代码**。

#### 元数据（Metadata）

编写代码之前，先在「元数据」页签定义插件的出入参：

-   **入参配置**：定义参数名称、描述、类型，AI 据此理解如何调用；
-   **出参配置**：定义插件返回的数据结构。

元数据与 HTTP 插件的出入参类似，是**代码插件与 AI 沟通的"接口契约"**。

> 💡 **最佳实践：元数据描述写得越详细，AI 调用插件就越准确。**

#### 代码（Code）

切换到「代码」页签，支持 **Python** 与 **JavaScript** 两种语言，内置代码编辑器并支持语法高亮。

**重点：支持 AI 代码助手。** 点击「代码助手」，用大白话描述业务需求，AI 自动生成代码框架，生成结果支持「替换」与「退出」，灵活迭代。

### 2.4 试运行与调试

配置完参数、写完代码后，点击「**试运行**」按钮即可即时调试：

1.  **输入参数** —— 填写测试入参；
2.  **点击运行** —— 立即执行插件；
3.  **查看调试结果** —— 右侧展示 JSON 返回，快速验证。

> 🛡️ **建议：发布前务必完成试运行验证，确保插件稳定后再上线。** 这一步能帮你躲过九成的问题。

### 2.5 发布与生效规则

当插件配置完成、调试通过后，点击「**发布**」。

**关键规则：插件只有发布后，智能体与工作流才能使用。**

| 生效范围 | 说明 |
| --- | --- |
| 🤖 **智能体可用** | 插件发布后，智能体才能调用该工具能力 |
| 🔗 **工作流可用** | 工作流中可以引用已发布的插件节点 |

> ⚠️ **安全迭代规则：** 编辑过程中的修改需**重新发布**才会生效，且**不会影响已发布的内容**。你可以放心大胆地改，不用担心改坏了影响线上正在使用的智能体。

## 三、Vibe Coding 方式创建插件

3.0 新增 **Vibe Coding 开发模式**——从"写代码"到"说需求"，**用自然语言描述需求，AI 自动完成插件开发**，让开发门槛降到"会说就会做"。

### 3.1 Vibe Coding 入口

3.0 首页新增 **Vibe Coding 入口**，支持四类开发快速进入：

-   🖥️ **网页应用** —— 对话式创建，发送消息自动建项目；
-   🤖 **智能体开发** —— 自然语言驱动智能体搭建；
-   🧩 **技能开发** —— 轻量级能力复用与封装；
-   🔌 **插件开发** —— 本文重点：用 AI 写插件。

### 3.2 实操①：对话发起开发

在首页 **Vibe Coding 对话框**，直接用自然语言告诉 AI 你想开发什么插件：

1.  选择「插件开发」入口，进入插件开发会话；
2.  输入需求，例如：**"帮我开发一个天气查询插件"**；
3.  无需编写代码，AI 立即开始搭建。

> 💡 **关键：用大白话说需求即可，AI 会帮你补齐技术细节。**

### 3.3 实操②：AI 自动完成开发

AI 自动完成插件开发，并**自动配置好元数据（出入参）**：

-   AI 分析后选用免费稳定的 **wttr.in** 天气接口，无需 API Key；（也可直接将接口文档和`apikey`告诉AI进行开发）
-   自动定义**入参**：`city`（城市）；
-   自动定义**出参**：`temperature` / `weatherDesc` / `humidity` / `windSpeed`。

> ✨ **亮点：元数据由 AI 自动生成，开发者无需手动编写。**

### 3.4 实操③：试运行验证

点击「试运行」，输入参数即可得到真实返回结果：

1.  输入城市参数，例如 `city = 成都`；
2.  右侧**实时返回 JSON**：天气、温度、湿度、风速；
3.  验证无误后，点击「保存 / 发布」上线。

### 3.5 Vibe Coding 开发插件完整流程

| 步骤 | 操作 | 说明 |
| --- | --- | --- |
| **1** | 进入 Vibe Coding，选择「插件开发」 | 每个引擎关联独立会话，复用网页应用的开发容器与隔离策略 |
| **2** | 用自然语言描述插件需求 | AI 自动编写提示词并保存到智能体配置；AI 优先复用平台已有工具，缺失能力可自由编码实现 |
| **3** | 沙箱中调试 | 支持选择固定框架（如 LangGraph），页面展示已生成代码的节点关系图 |
| **4** | 发布打包 | 发布时打包为可执行文件，支持按版本缓存；涉及外部密钥时自动创建变量供你配置 |

## 四、总结：两条开发路径

开发插件有两条路，按需选择：

### 🔧 一般创建插件的方式（标准四步）

> **选方式 → 配参数 → 试运行 → 发布**

-   选方式：有接口用 HTTP，没接口写代码；
-   配参数：填好 URL、元数据、出入参；
-   试运行：调试验证，确保稳定；
-   发布上线：发布后智能体和工作流就能用。

### ⚡ Vibe Coding 方式（零门槛）

> **说需求 → AI 生成 → 沙箱调试 → 打包发布**

-   全程自然语言驱动；
-   AI 优先复用平台已有工具；
-   开发门槛低到"会说需求，就能做插件"。

> **核心要点：插件 = 智能体的工具扩展层。先掌握一般创建方式，再进阶 Vibe Coding，两条路都能打造出强大的智能体能力！**

## 五、常见问题（FAQ）

**Q1：HTTP 插件和代码插件怎么选？**

有现成的接口 / API → 用 HTTP 插件；需要自己写新逻辑 → 用代码插件。

**Q2：「自动解析」是什么？**

填写好 HTTP 接口和请求参数后，点击「自动解析」，系统会自动解析接口返回的数据结构，把输出参数自动补齐，无需手动定义出参。

**Q3：为什么要先「试运行」再发布？**

试运行可以即时调试，左侧输入参数、右侧查看 JSON 返回结果。发布前完成试运行验证，能确保插件稳定可靠，避免上线后出错。

**Q4：修改插件后需要重新发布吗？**

需要。编辑过程中的修改需**重新发布**才会生效，且重新发布**不会影响已发布的内容**，可以安全迭代。

**Q5：Vibe Coding 需要会写代码吗？**

不需要。用自然语言描述需求即可，AI 会自动完成代码编写、元数据配置和调试，开发门槛极低。
