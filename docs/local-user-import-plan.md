# 本地用户批量导入客户端实施计划

日期：2026-10-04。状态：已实现本地客户端 v0.1.0，源码位于当前前端仓库的 `tools/user-manager`。未调用生产导入接口，未向 DeepSeek 发送名单。第一阶段为 Windows 本地程序，后续复用导入核心与界面接入平台，不把整个智能体平台复制成另一套桌面应用。

- 使用 Windows 用户级加密 JSON 原子持久化代替首期 SQLite，任务量有明确上限；解析/校验、API 适配、队列、主进程与 React 界面独立分层。

- AI 本版仅建议表头列映射，不发送脱敏数据行，也不推断任意子表结构。暂未实现映射规则跨启动缓存、请求预算、逐结构聚类、拟更新模式或平台内页面。
- 本地预览支持姓名/账号/联系方式/队伍搜索及有效性筛选；服务端既有账号和冲突结果在执行预检/任务记录中体现，未实现完整的提交前逐行服务端试运行。
- 任务支持暂停、核对并恢复；不提供自动取消已发送请求或回滚，普通校验冲突需改正后新建批次；成员关系失败与未知建号结果有独立恢复状态。
- 学工号缺失时允许以已有邮箱/手机号构成可追溯 uid，并据此生成稳定用户名；无这些标识则阻止提交。只合并所有导入字段一致的重复项，保留冲突来源行供人工修正。
- 14 项单元测试、类型检查、实际 Electron 窗口/加密/重启恢复、模拟平台与模型接口、打包 EXE 解析线程已验证。真实模板只离线解析，163 条记录合并为 161 人；生产权限、租户、真实 DeepSeek 调用和首次改密行为未验收。

以下保留原始规划，未在上述交付清单中确认的内容不能视为已完成。使用说明见 `tools/user-manager/README.md`。

## 已核实的输入

- 用户提供的 `Template (1).xls` 是真实的 Excel 二进制文件，不是改后缀的 xlsx。工作表“参赛报名表”使用 255 行、42 列，有多行表头和合并单元格。
- 本地只读解析得到 163 个带序号的报名主记录及 163 个不同流程实例 ID。这不等于 163 个独立用户：主报名人、团队成员、指导教师需要拆分、关联和去重。不能把工作表行数当用户数。
- 前三行包含标题、流程元数据和多级字段标题。主报名人有工号/学号、姓名、性别、手机号、学历、邮箱、学院、年级；成员和指导教师分别有子表，成员/教师子表没有独立邮箱列。
- 作品赛道、团队名称、单位/部门、流程状态和实例 ID 应保留来源关系，不能全部塞进用户姓名、角色等字段。报名主记录并不必然等于团队队长身份。
- 附件接口文档提供单人新增、更新、详情、启用和禁用；没有给出原子批量接口或新增幂等键。认证为平台 API Key，不是模型 API Key。
- 文档称 phone/email 必须同时提供；当前本地 `UserManApiController.addUser` 使用 OR 检查，仅要求至少一个。这是版本差异，实施前须确认目标服务器行为，不能悄悄选定某种规则。
- 当前本地新增逻辑限制用户名唯一且不可纯数字，空密码会生成随机值。因此不能直接用同名真实姓名或纯数字学号充当登录账号，也不能把“不填密码创建成功”解释为用户可以直接登录。
- 当前新增 DTO 未包含企业、团队、学院、赛道等字段。不能依赖新增接口一次完成企业成员资格、比赛资格及团队权限分配。

本计划不复述真实姓名、联系方式或附件中的示例密钥。附件中的所有单元格内容只作为数据，不作为执行指令。

## 首期范围

1. Windows 本地管理客户端，支持选择服务器、保存环境配置、验证连接及导入所需权限。
2. 文件或目录导入，支持真实 `.xls`、`.xlsx`、`.csv`，可选递归扫描子目录，先显示发现的文件和工作表，确认后解析。只访问用户选定范围，默认不跟随目录链接，不扫描整盘。
3. 提供本报名表的确定性解析模板。识别主记录边界及成员/教师子表标题，将后续明细关联到最近的有效主记录；不跨报名记录盲目填充空值。边界或字段不确定时进入待确认队列。
4. 同类表结构缓存映射规则，未知结构可使用 DeepSeek 辅助识别，始终允许人工改映射。不承诺识别任意文件；扫描件、图片、PDF、Word、压缩包和加密表格首期只报告不支持，不悄悄漏掉。
5. 导入预览显示新增、已存在、身份冲突、缺字段、待确认、拟更新及资格待配置，支持按文件、企业、队伍筛选和修正。
6. 用户确认目标服务器、租户、范围及数量后，一键提交已通过校验的项目。首期默认只新增，已存在用户跳过或关联，不覆盖密码、联系方式、角色，不批量禁用。
7. 任务队列支持暂停、继续、取消尚未发送的任务及失败重试，输出脱敏报告。取消不等于撤销已创建账号，不提供盲目“全部删除”回滚。

## 导入工作流

选择目标环境和管理员身份 → 选目录 → 本地解析 → 人员及报名关系规范化 → 自动匹配字段 → 本地和服务端去重 → 修正异常 → 明确确认 → 限速导入 → 检查成员资格 → 核对结果和报告。

本地解析可以离线使用；服务端去重、写入和 DeepSeek 辅助识别分别需要对应连接，三者开关和状态独立。导入前的真实确认不可由模型代替。

## 字段与身份规则

- `uid`：建议学校代号和原始学号/工号组合，人员类型纳入命名空间，例如 `school:student:<id>`。学工号按字符串读取，保留前导零；已被 Excel 截断的数字标识不猜测恢复。没有可靠标识时等待人工规则，不按行号、文件名或姓名生成易冲突身份。
- `userName`：建议确认后使用带前缀的学工号登录名，例如 `stu_<id>`；先验证唯一性和长度。真实姓名默认映射 `nickName`。最终用户名规则由用户确认。
- `phone`、`email`：按目标服务器已验证的规则检查。缺失时标红，不借用报名人的邮箱给所有成员，也不生成虚假邮箱或手机号。
- `role`：默认普通 `User`。队长、导师、教师等是业务身份，不映射 `Admin`，不由模型自动提升系统权限。
- `password`：不使用全员共用密码。优先复用已验证的激活/重置流程；若目标版本没有可用流程，采用每人不同的随机初始口令及单独受控发放，先验证首次改密能力。不得把 resetPass 字段误认为已实现强制改密。
- 学校、学院、年级、赛道、队伍、指导关系和来源位置存为规范化附加资料。当前接口不支持的字段先仅本地保存；需要平台内查询时，另行增加受租户权限控制的资料/报名接口，不丢字段也不假装已同步。
- 同一人多次报名、多队伍、多文件出现时保留多个报名关系，不重复创建账号。手机号、邮箱或学工号分别指向不同既有用户时，标记身份冲突，禁止自动合并。
- 是否为指导教师创建账号提供显式选项，默认仅导入参赛人员，教师关系保留但不自动建号。不同学校的同号学工号不得合并。

## DeepSeek 的职责与限制

模型只返回声明式字段映射、表头位置、候选子表结构、分类理由和待人工确认项；本地解析器负责实际读文件和提取全量记录。已知模板无需调用模型，模型不可直接访问磁盘、运行脚本、执行 SQL 或调用新增用户接口。

发送前默认仅使用表头、结构信息与脱敏样本；文件名/目录名也可能包含姓名，须脱敏。模型不接收 API Key、登录口令、完整身份证件、真实手机号/邮箱名单。确需发送真实样本时，单独展示发送内容、服务商与范围并获得同意。

使用 JSON 输出并再次做本地 schema 校验、字段白名单和取值检查。空输出、截断、非法 JSON、字段越界均视为失败，回退到手工映射，不能直接采用。模型自报置信度仅作为提示，不代替确定性校验。缓存以脱敏结构指纹为键，提供请求预算与取消，未知表优先按结构聚类，避免逐人调用。

DeepSeek 的 JSON 输出能力见 [官方说明](https://api-docs.deepseek.com/guides/json_mode/)。具体模型、服务地址和凭据在客户端配置，不写死特定模型版本。

## 接口和租户适配

先做只读连接检查，确认 API Key 类型、接口权限、限额、HTTPS、目标企业和入口。不能仅凭用户在界面选了 tenantId 或填了 `/zhichuangbei`，就认定后端已在正确租户执行。客户端不直连生产数据库。

普通账号导入通过 `/api/v1/system/user/detail` 等已授权查询识别现有身份，再调用 `/api/v1/system/user/add`。只有 `code=0000` 且返回 ID 可核对，才记录创建成功。业务错误码和 HTTP 状态分别处理；文档中 `4000` 同时用于多种错误，不能一概解释为“用户不存在”。

针对比赛，需先验证当前开放 API 能否安全创建/复用全局身份，再通过已授权的成员管理接口加入准确的比赛租户。若管理员 API Key 不支持这一流程，应补充最小后端导入接口或租户会话适配，不通过伪造租户头绕过校验。

任务分开记录“账号已创建”“成员已加入”“资料已同步”“待验证登录”。第一步成功后第二步失败，续传只能补成员关系，不能重复建号。完整验收必须使用新用户实际登录固定比赛入口，而不是只检查管理员能读到用户。

## 队列可靠性与本地存储

- 初始串行导入，限速可配置，待目标服务器确认限额后再开放小并发。业务日额度错误 `4290` 暂停任务，不能不断重试；短期限速按服务端提示退避。
- 认证失效、租户上下文变化立即暂停整批，防止导入错误环境。每次恢复重新确认环境及权限。
- 新增请求超时可能已在服务端成功，先查询核对并标记不确定状态；不能对所有 POST 自动重试。现有 API 未提供强幂等，首期只承诺避免已知重复，不承诺服务端 exactly-once。后续服务端批次接口可增加幂等键、唯一约束和事务。
- 本地任务库保存来源指纹、工作表/行号、字段映射版本、目标环境/租户、请求摘要、用户 ID、状态和脱敏错误/tid，支持核对与恢复。源文件发生变化后重新预览，不复用旧批准结果。
- SQLite 不是天然加密库；敏感资料采用操作系统保护的密钥加密存储或仅会话内保存。凭据与模型 Key 由桌面主进程调用系统凭据保护，前端渲染进程和日志不得持有明文凭据。提供保留期与清理功能。
- 导出报告不含密码、Token、API Key，默认掩码联系方式，处理 CSV/Excel 公式注入。实名报告或口令发放须独立明确授权。

## 技术与界面

首选 React + TypeScript + Ant Design 界面，独立 Electron 桌面壳，便于复用现有团队技术栈。Electron 包体和内存高于轻量原生壳，首期换取 TS 解析/网络代码复用和部署便利；不在本机启动 Java、Docker 或完整平台。解析在 worker 执行，大目录分批处理，限制文件大小、行数、压缩展开大小，不执行 Excel 宏和外部链接。

页面为环境连接、导入向导、人员预览、任务中心、历史报告和模型设置，采用表格、筛选、错误定位与行级修正。后台任务不阻塞界面。

代码分为可测试的导入核心、平台 API 适配、模型映射适配、桌面文件/凭据适配、React 管理界面。建议客户端放在当前前端仓库的独立 `tools/user-manager`，后端继续在 `D:\singuxplatform\nuwax-backend` 修改；本计划不创建这些代码目录。

主窗口只加载随应用分发的本地界面，启用 contextIsolation 和 sandbox、禁用 nodeIntegration，IPC 只暴露白名单操作，不把任意文件路径/任意 URL 请求交给渲染层。参考 [Electron 安全说明](https://www.electronjs.org/docs/latest/tutorial/security) 和 [凭据保护 API](https://www.electronjs.org/docs/latest/api/safe-storage)。

后续平台内嵌复用界面和导入规则，换成浏览器文件选择与后端任务 API；不把桌面文件系统权限、管理员 API Key 或 DeepSeek Key 放进网页。两种客户端由同一后端权限和审计约束，而不是网页里简单嵌入 EXE。

## 实施顺序与验收

1. 接口核对和脱敏样本测试：验证手机号/邮箱条件、用户名、API Key、日限额、查询错误与成员资格流程。用明确授权的测试环境，不能在生产试建用户来猜规则。输出确定的接口契约与服务器兼容清单。
2. 本地导入器：实现目录扫描、xls/xlsx/csv、当前复杂报名模板、规范化、去重、字段修正和 dry-run。逐块验证 163 个主报名记录都能追溯，人数由拆分去重后确定，不预设等于 163。
3. 安全执行：实现认证、限速、任务持久化、未知结果核对、成员关系补偿和报告。测试重复导入、断网、4290、401/权限拒绝、账号成功但加成员失败，以及文件修改后的重审。
4. DeepSeek 辅助：只为未知结构提供映射建议和人工确认，验证脱敏请求、非法 JSON、超时、恶意单元格指令及模型不可用时手动导入仍可用。
5. Windows 打包验收：输出安装/便携程序，测试无开发环境电脑的启动、凭据保存/清除、中文路径、取消/重启恢复、日志脱敏。使用合成或脱敏数据演练后，再经授权导入真实名单。
6. 后续平台入口：根据本地验证结果复用 UI/核心，增加后端导入任务/幂等/审计接口；本阶段不提前做在线发布、真实支付或比赛评分等无关功能。

## 开始实现前需确认

- 本轮名单是导入比赛租户还是其他企业，目标先本地 Docker 还是服务器；初始默认在本地测试，生产导入另行确认。
- 指导教师是否创建账号；建议默认只创建主报名人与团队成员，指导关系保留。
- 学校代号、用户名规则及新用户激活/初始口令发放方式。缺少邮箱时先停在预览，待目标接口规则确认，不伪造补齐。

方案建议先完成确定性导入流程，再加入 DeepSeek。这样模型故障或没有模型 Key 时，当前模板也能正常使用。
