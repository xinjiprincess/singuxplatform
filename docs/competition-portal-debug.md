### 本轮调试记录

1. 新租户不能使用空 `domain`：历史域名映射 `toMap` 遇到重复空值会让所有登录失败。比赛租户使用唯一内部占位 `zhichuangbei.portal.invalid`；不要求真实 DNS。
2. Nginx 原 `Host $host` 丢弃本地端口，Origin 校验失败。改为 `$http_host`，保留完整访问 authority。
3. 本地 admin 缺少首次使用单位资料：只为该测试管理员沿用已有企业名“Singu X平台”，不取消普通用户首次资料流程。
4. 新租户菜单/角色来自内置 `permission-1.4.json`。通过原平台管理员的 `/api/system/permission/import?tenantId=4&version=1.4` 初始化本地比赛租户；不复制业务资源。
5. 初始化后菜单仍为空：旧 `userBindRole/userBindGroup` 按用户最初租户查询，跨企业成员报“用户不存在”。新增 `TenantRbacUserResolver`，先验证当前企业有效成员，再读取身份并采用成员角色；不把全局 Admin 权限带入普通成员租户。新增 4 项回归通过。
6. 原主题初始化覆盖比赛色：在统一主题数据入口应用 portal accent。
7. Umi 与 XHR 同时加入口头会形成重复值，后端正确拒绝为 Unknown portal；改为仅由底层 fetch/XHR 适配添加一次。必须用最终浏览器构建复核，单独 HTTP 脚本无法发现这个问题。
8. 前端 4 个测试文件共 10 项通过：路由、缓存分区、fetch/XHR 范围、未知入口失败及文档菜单过滤。
9. 第一轮 12 项接口检查通过：公开配置、比赛登录、租户 profile、跨入口拒绝、切换/管理拒绝、官网登录/选择、管理列表和审计保存。补充菜单及停用恢复的最终结果在本节后续记录。
10. MyBatis-Plus 的防全表更新拦截器不支持前缀 `BINARY` 比较语法，管理保存曾报 5000。改用 `CAST(... AS BINARY)` 并增加 `PortalMapperSqlTest`，不关闭拦截器或并发比较。
11. 本地种子原来带有官网默认智能体 ID。新租户清空默认/推荐智能体引用；种子仅首次初始化时清空，不覆盖后续运营配置。RedisUtil 的配置键使用序列化格式，失效操作限定 `tenant_config:4` 后缀，不清空 Redis。
12. 新租户默认智能体为 0 时，旧首页仍请求详情，触发“已下架”。首页增加有效 ID 判断；未配置时不发无效请求，发送时提示未配置。
13. 最终后端镜像 `04c3f8d926c1a342940a5051945a125ff85ed916d97883318d0a29e7999de669`：61 项选定测试通过；运行健康。最终 API 脚本 18 项全部通过，含菜单初始化、审计保存、停用后拒绝旧会话、官网管理保持可用、恢复启用。前端包含原有登录分流的 5 文件共 25 项测试通过。

## Debug 排查顺序

1. 白屏：先看文档及 JS/CSS HTTP 状态、Content-Type、资源基路径和控制台异常，再看入口解析是否完成；禁止直接清空全部站点存储掩盖问题。
2. 未登录或循环跳转：对照入口解析、会话受众、缓存命名空间、网关前缀和 redirect 允许列表；日志不输出 Token、密码或密钥。
3. 串品牌/数据：检查公共配置缓存键、portalId/tenantId 一致性、晚到响应和 SQL/对象/索引过滤；立即停止外部试用，不以刷新页面作为修复。
4. 流式中断：核对入口 API 路径、代理缓冲、超时、鉴权和撤销；记录 requestId 与任务 ID。
5. 模型失败：检查配置 URL 协议和端口、上游状态码、流解析及终止事件；禁止把 null 输出、0 Token 或缺失结束时间记作成功。
6. MCP/沙箱/网页应用失败：从后端到实际服务检查 DNS、端口、凭据、依赖安装、健康与工具握手、资源限制及退出码。健康检查不能替代真实调用。

日志建议统一字段：requestId、portalId、tenantId、actorId（必要时脱敏）、资源/任务 ID、阶段、结果、错误码、耗时。不上报模型全文输入、文件内容或密钥。
