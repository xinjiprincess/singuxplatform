## 0. 实施状态（2026-09-27）

第 3、4 节描述的「登录 -> 身份会话 -> 选择企业页 -> 企业会话」主流程已实现，并在本机 Docker 环境用真实请求验证：登录只返回 `stage=TENANT_SELECTION_REQUIRED` 与 HttpOnly `ticket`，不返回访问令牌；持票据可列出本人企业；选定企业后返回携带 `tenantId` 与 `membershipVersion` 的企业令牌。详见 `VERSION_CHANGES.md` 同日条目。尚未完成：真实浏览器人工验收、邀请、无企业用户状态、所有权转移，以及第 9 节的完整数据隔离矩阵。

实施中发现两处与本文假设不一致，实施前需先决策：

1. **建企业的初始状态**：`addTenant()` 建出的企业 `status` 为 `Pending`，而第 4 节的会话校验（`requireActive`）要求企业 `Enabled`。因此新企业即使已为创始人写入 OWNER 成员关系，在管理员启用该企业之前仍无法进入。方案需要明确这里是「审批后启用」流程，还是建好即可用。
2. **品牌规则**：第 11.1 节要求「统一入口永远使用 Singu X 平台品牌」，但已确认的新需求是企业各自设置登录页背景图与智能体页背景图，二者直接冲突。该节将在背景图批次一并修订，不能按现文实现。

## 3. 登录页与企业选择体验

### 3.1 主流程

```text
访问 www.ciyuancenter.cc/login
  -> Singu X 品牌登录页：用户名/邮箱/手机号 + 密码
  -> 身份验证成功，获得短时“待选择企业”会话
  -> /login/enterprises：选择企业
  -> 后端重新校验该企业、成员和入口资格
  -> 签发企业会话，加载本企业品牌、菜单、空间
  -> 进入本企业工作台
```

企业选择页与登录页使用同一品牌、语言和视觉框架，是登录的第二步，不挂在工作台侧栏下面。用户能清楚看到自己正在为哪个账号选择企业。

### 3.2 页面结构与行为

| 区域 | 内容与行为 |
| --- | --- |
| 顶部 | 平台 Logo、Singu X 平台、语言选择；保留已完成的中文默认文案 |
| 标题 | “选择企业”；脱敏账号信息；“切换账号”操作 |
| 查询 | 搜索本人已加入的企业名称或代号；后端分页，不请求全平台企业目录 |
| 企业行 | 企业名称、代号、当前角色、可访问状态；付费且有权益的品牌图标，免费企业使用平台统一图标 |
| 选择 | 单选企业，显示选中状态；明确的“进入企业”按钮；请求期间禁用重复提交 |
| 便捷项 | “上次使用”仅排序提示；本期默认仍要求确认，不自动进入第一家企业 |
| 其他入口 | 有邀请时显示接受邀请入口；独立平台管理员显示“平台管理”，不伪装成一家企业 |

桌面使用紧凑可扫描列表，移动端单列且不横向溢出；键盘可完成搜索、单选和提交，加载/错误状态有可读反馈。文案通过 `PC.Pages.TenantSelect.*` 管理，不硬编码英文；企业名称、Logo 和角色必须来自服务器。

### 3.3 必须处理的状态

| 状态 | 处理 |
| --- | --- |
| 未登录 | 只显示登录表单；不暴露用户所属企业和全平台企业名单 |
| 正在验证身份 | 保持表单，防重复提交；验证码或密码错误不泄露账号/企业是否存在 |
| 正在加载企业 | 选择页显示稳定尺寸的加载状态，不渲染空工作台 |
| 只有一家企业 | 显示这家企业并预选，用户点击进入；未来自动进入可作为用户可撤销偏好 |
| 多家企业 | 用户明确选择；不得依赖最小 tenantId 或旧 UserInfo.tenantId 决定目标 |
| 没有企业 | 显示“尚未加入企业”、接受邀请/切换账号；不自动加入默认企业 |
| 企业暂停或初始化失败 | 已授权用户看到不可进入状态；可联系企业管理员或重新选择 |
| 成员被撤销 | 重新读取列表，目标不可进入；过期邀请不能恢复资格 |
| 身份会话过期 | 回登录页，清除选择草稿；不能无限请求或跳转 |
| 无业务菜单 | 显示无权限/企业未就绪页面、企业切换和退出入口，不静默空白 |
| 查询/选择失败 | 可重试；不能用缓存中的另一家企业替代 |

登录前可提供“企业入口”操作，允许输入已知企业代号/访问邀请链接，或按已验证自定义域名显示公开品牌，但不显示全平台企业下拉列表。输入代号只记录目标，不授予权限；验证身份后仍须校验 membership。自定义域名不展示其他企业的列表，跨企业切换引导回统一平台入口。

## 4. 会话模型与安全边界

### 4.1 三类会话分离

| 会话 | 可访问接口 | 禁止事项 |
| --- | --- | --- |
| IDENTITY：已验证身份、未选企业 | 本人身份摘要、本人企业列表、选择企业、邀请接受、退出 | 不能查询工作空间、聊天、用户管理、文件或其他租户业务 |
| TENANT：企业会话 | 当前企业授权范围内的业务；可受控发起企业切换 | 不能因 userId 相同或角色名为 Admin 而跨企业访问 |
| PLATFORM：平台管理会话 | 租户生命周期、全局套餐、平台审计和受控支持入口 | 平台权限不隐式变成所有企业的数据读取权限 |

IDENTITY 设计默认有效期 5 分钟，服务端可配置，支持选择失败后的有界重试。推荐不透明随机票据、服务端保存摘要和状态，经同源 HttpOnly Cookie 携带；正式 HTTPS 启用 Secure、SameSite 和 CSRF 保护。不得将身份票据作为现有 ACCESS_TOKEN 使用，不放在 URL 中。

TENANT 会话必须包含或服务端关联 `userId、tenantId、membershipVersion、sessionId、sessionGeneration、purpose、expiresAt`。签名验证只是第一步，还需校验账号/企业/成员/会话状态及入口域名。租户停用、账号停用、成员撤销、角色变更和退出均需生效；刷新令牌也不能绕过撤销。

采用服务端可撤销会话记录；浏览器访问令牌逐步迁移为内存态，续期凭据放 HttpOnly Cookie，刷新使用单次轮换并检测重放。现有 localStorage + Cookie 混用必须有兼容迁移，禁止旧 Cookie 覆盖新 Authorization。桌面/API Key 接入不复用浏览器 Cookie 流程。

### 4.2 选择企业的原子流程

1. 校验 IDENTITY 会话、来源、过期时间和选择请求幂等键。
2. 校验 tenant 已启用且权限初始化就绪、membership 有效、目标符合入口 Host 约束。
3. 在同一选择事务/状态转换中锁定该身份会话，创建企业会话；同一票据并发选择不同企业至多一个成功。
4. 返回最小企业摘要和会话信息；设置 Cookie 的范围和属性，响应 `Cache-Control: no-store`。
5. 前端才加载企业公开配置、用户有效角色、菜单和默认工作空间，完成后进入工作台。

客户端网络超时重试必须能识别已完成的同一选择，不重复创建并行会话；票据被消费后不能凭旧凭据选择另一个企业。无企业用户仍可保持受限身份流程，不以业务登录失败掩盖该状态。

### 4.3 企业切换和多标签页

- 切换前检查编辑器未保存内容、上传和运行任务，提示用户确认；后台任务继续归属原企业，不能随浏览器切换改变归属。
- 服务端锁定当前浏览器会话族并校验 generation，目标检查全部成功后原子替换活动企业会话。失败不先销毁旧可用会话；成功后旧 generation 的请求/续期被拒绝。
- 同源标签页通过 BroadcastChannel/storage 事件同步会话代次，但不广播令牌；收到切换后停止请求并进入切换/重新加载状态。
- 终止 SSE/WebSocket、轮询、上传和预览订阅；服务器也须撤销或有界复验长连接，不能仅检查建立连接的一刻。
- 所有请求与响应带客户端上下文代次校验，覆盖 Umi request、fetch、流式 reader、Worker、定时器和 AppDev iframe 通信。晚到的旧企业响应必须丢弃。
- 清理用户、菜单、空间、聊天、资源、主题和离线缓存；持久化键包含 host/userId/tenantId。记住企业只存偏好，不能存授权结论。

## 6. 后端与接口契约

### 6.1 必改模块

- `AuthServiceImpl`：将验证凭据与创建企业会话拆开；密码、验证码及其他登录入口结果一致；移除新版流程中 `bindLogin()` 自动选租户的行为。
- `TenantMembershipService`：允许先验证全局身份再列成员；角色不写回全局 user；支持邀请、受限管理员操作、所有者转移和离职撤销。
- `TenantSessionService`：初次选择与切换分别处理，增加会话族、幂等、并发版本及刷新/撤销协议。
- `AuthInterceptor`、权限服务：按 purpose 区分接口，建立不可由请求体覆盖的 TenantContext；普通业务缺上下文时拒绝。
- `TenantPolicyApplicationService`：统一权益读取；FREE 自定义 Logo/域名硬拒绝；域名申请、上传品牌、写配置等所有路径采用同一校验。
- 企业创建服务：事务写基础实体及 outbox，异步初始化资源和权限，只有全部就绪才开放登录。

### 6.2 接口设计（新增均为拟实施，非已存在）

保持现有 ReqResult/code 响应封装，版本化升级时兼容旧调用方；不为追求 REST 风格重写全库。

兼容不允许形成绕过入口：服务器启用新版多租户认证后，旧 passwordLogin/codeLogin 也必须适配为受限身份流程，或向不兼容客户端返回明确升级要求；不能继续签发自动选企业的旧式业务令牌。authFlowVersion 由服务器决定，客户端不能传参数退回宽松模式；旧令牌作废与重新登录需要纳入灰度计划。

| 接口 | 会话/授权 | 作用 |
| --- | --- | --- |
| `GET /api/public/tenant/resolve` | 匿名，可信 Host | 返回 PLATFORM/TENANT 入口、公开品牌、authFlowVersion、登录方式；不返回企业目录 |
| `POST /api/auth/identity/login` | 匿名，限流/验证挑战 | 验证密码，签发 IDENTITY；其他认证入口汇入同一服务 |
| `GET /api/auth/identity` | IDENTITY | 刷新选择页时确认身份、剩余有效期和限定目标 |
| `GET /api/me/tenants` | IDENTITY 或合适的 TENANT | 只查本人已加入企业，支持分页与关键词 |
| `POST /api/session/tenant/select` | IDENTITY | 幂等地消费身份票据并创建企业会话 |
| `POST /api/session/tenant/switch` | TENANT | 校验目标资格、会话代次及幂等键后切换 |
| `POST /api/session/refresh`、`/logout` | 对应会话 | 受控轮换或撤销；不因刷新扩大权限 |
| `POST /api/session/platform/select` | 受控身份，独立平台授权 | 创建 PLATFORM 会话，建议要求近期认证/MFA |
| `GET/POST /api/platform/tenants` | PLATFORM | 列表/创建企业；创建使用幂等键 |
| `PATCH /api/platform/tenants/{id}` | PLATFORM | 状态和基本资料，带 version/reason |
| `/api/tenant/members`、`/api/tenant/invitations` | TENANT 管理权限 | 成员管理、邀请、撤销；所有权转移另列接口 |
| `GET /api/tenant/profile`、`PUT /api/tenant/brand` | TENANT 对应权限 | 资料与受权益保护的品牌 |
| `/api/tenant/domains`、`/{id}/verify` | TENANT 对应权限与 PAID 权益 | 域名登记、验证、状态、解绑 |
| `/api/tenant/entitlements`、`/api/tenant/usage` | TENANT | 权益、配置限额、已用/预留及未配置状态 |
| `POST /api/tenant/members/export` | TENANT 成员导出权限 | 白名单数据、导出审计、快照/版本语义 |
| `GET /internal/domains/allow-certificate` | 仅受信网关网络 | 精确判断某个 host 能否签证，拒绝未知域名 |

身份会话不因上述“本人企业”接口而获得普通业务接口访问权。401 身份失效、403 无资格/域名不匹配、409 并发变化、429 限流和可重试未就绪状态应有稳定业务码及前端对应状态；不能全部返回“Network error”。

登录结果示意：认证阶段返回 `{ stage: "TENANT_SELECTION_REQUIRED", identityExpiresAt, entryMode }`，凭据使用受控 Cookie；选择成功返回 `{ stage: "TENANT_READY", tenant: { id, code, name }, role, sessionGeneration, expiresAt }`。不返回完整 user 实体、密码字段或平台私密配置。

## 7. 成员、角色与用户列表

| 身份 | 允许 | 禁止 |
| --- | --- | --- |
| 平台管理员 | 创建/停用租户、套餐配置、受控平台支持、全局身份安全管理 | 未审计地模拟企业成员、借普通业务 API 读全部企业数据 |
| 企业所有者 | 本企业成员管理、所有者转移、品牌域名与套餐查看 | 移除最后所有者、授予平台权限 |
| 企业管理员 | 在授权范围管理普通成员及企业设置 | 直接提升为所有者、移除所有者、管理其他企业 |
| 企业成员 | 被授权空间、智能体、文件等资源 | 因具有 membership 就访问企业全部空间 |

有效权限为：账号有效 ∩ 企业有效 ∩ membership 有效 ∩ 企业角色/策略 ∩ 空间/资源授权。保留 OWNER 与 ADMIN 的业务差别，不能仅映射旧 Admin 后丢失所有者限制。

用户是全局身份，企业成员是关系。企业管理员移除成员只撤销本企业关系，不能删除全局用户、重置该用户全局密码或影响其他企业。现有 UserManage 的禁用/删除/重置密码操作要拆成“平台账号管理”和“企业成员管理”，相关按钮、服务和后端接口一并调整。

邀请使用高熵一次性令牌，数据库只存摘要，绑定企业/目标身份/角色/过期时间；接受时验证当前身份和席位，事务防重。非成员不能仅凭企业 ID 加入。成员撤销清理本企业 API Key/会话/空间关系或标记失效，其他企业资格不受影响。

用户导出延续字段白名单和 CSV 公式防护；企业端只导出本企业可见成员，不带其他企业列表。平台跨企业导出使用独立权限、范围和审计，不复用前端传 tenantId 的普通列表接口。规模变大时用服务端快照与短时鉴权下载，不把当前 10,000 条前端分页实现称为一致性全量快照。

## 8. 数据模型与迁移

以下是逻辑实体清单。先盘点现有 tenant/user/policy/订阅表，已有可用字段复用，不重复建表。

| 实体 | 关键约束 |
| --- | --- |
| global_user | 唯一身份和凭据，账号启停；历史重名先清理，不自动合并用户 |
| tenant | 唯一 code、name、status、bootstrap_status、permission_version、version |
| tenant_membership | 唯一 (tenant_id,user_id)、角色、状态、version；至少一名有效所有者 |
| tenant_invitation | 目标身份、角色、令牌摘要、到期和接受状态；幂等接受 |

| platform_role_assignment | 与企业角色独立；权限变更审计 |
| tenant_brand | 企业归属的资产引用、公开展示名、主题版本；不是任意外链 CSS/HTML |
| tenant_domain | 全局唯一规范化 host、所有权验证、路由/证书状态、有效权益版本 |

| tenant_audit_log / outbox | 操作者、企业、动作、对象、结果、关联请求 ID；不记录明文凭据 |

迁移顺序：

1. 备份并演练恢复；记录原账号、企业、资源、权限和上传数据数量；只读生成冲突清单。
2. 增加成员与会话等必要结构，不删除 user._tenant_id 兼容字段；按已有归属回填，不把所有数据改成 tenant 1。
3. 审核默认所有者。现有迁移“有效 Admin 最小 ID”仅是候选规则，生产需人工确认。
4. 处理用户名/邮箱/手机号规范化后的冲突；保留原用户 ID、密码兼容和历史审计归属，不自动合并身份。
5. 分模块对照新旧查询结果，补租户索引/唯一约束和缺失归属；归属不明数据隔离待核对，不无条件公开。
6. 在完整测试库启用新登录和选择企业；迁移会使旧不带新声明的会话失效，公告要求重新登录。
7. 完成跨企业测试和对账后灰度；新跨租户写入出现后禁止直接回滚到未隔离旧代码。

## 9. 完整数据隔离检查矩阵

以“入口 -> 授权 -> 查询/写入 -> 缓存 -> 异步 -> 导出/分享”为单位出清单，不只按表是否含 tenant_id 判断完成。

| 层面 | 必须完成的措施与验证 |
| --- | --- |
| MySQL/ORM | TenantContext 服务端生成；检查 MyBatis 拦截器、原生 SQL、join、统计、分页、批量和删除；禁止读取请求体 tenantId 覆盖上下文 |
| 全局例外 | 全局身份、套餐模板、平台运营任务采用受控显式入口；审计所有 `@InterceptorIgnore`，不允许通用“忽略租户”开关暴露给客户端 |
| 工作空间/资源 | 空间、智能体、工作流、技能、插件、知识库、聊天、页面应用逐一验证归属和细粒度权限；引用/复制也校验来源与目标 |
| 自定义数据库 | 本地配置还使用 agent_custom_table；数据库/表名映射服务端限定，覆盖动态 SQL、执行器、导入导出，不能只改主业务库 |
| Redis | key 包含企业维度及必要用户/资源 ID；分布式锁、幂等键、限流、缓存失效均隔离；身份验证码单独全局命名空间 |
| 本地文件/MinIO | 两类存储均盘点；租户前缀、元数据归属、路径防穿越、鉴权下载/短时签名、配额及删除校验；不能只靠不可猜 URL |
| Elasticsearch/Milvus | 写入与查询、聚合、删除、向量检索均强制企业条件；客户端不可覆盖过滤器；缺失上下文拒绝 |
| 任务/线程池 | 消息带经过验证的企业/主体/资源上下文，执行时复验，处理重试/死信/定时任务，finally 清理线程上下文 |
| SSE/WebSocket/AppDev | 连接和每次敏感输出保持企业绑定，撤销与切换后旧订阅失效；预览、文件树、构建产物和日志都属于原企业 |
| API Key/模型凭据 | 企业绑定、最小权限、吊销、加密/脱敏；禁止 B 企业使用 A 企业模型密钥或余额 |
| 分享/发布/广场 | 私有、企业内、公开资源有明确策略；公共仅暴露发布快照，禁止沿引用读私有源；撤销分享失效 |
| 导出/批量操作 | 逐项检查归属，混入其他企业 ID 时拒绝，不返回额外资源是否存在；下载链接仍受授权 |
| 外部执行服务 | 代码执行、构建、日志、沙盒、Agent 服务采用可信服务凭据和企业上下文；尚未验证的服务不开放多租户 |
| 备份/日志 | 数据库和数据卷备份含多企业敏感信息，仅运维可访问；企业管理员不能下载全平台备份，日志按权限查询 |

本方案采用共享表方案，不承诺数据库天然提供行级隔离；应用授权和存储访问必须可测试、可审计。隔离检查维度参考 [OWASP 多租户安全指南](https://cheatsheetseries.owasp.org/cheatsheets/Multi_Tenant_Security_Cheat_Sheet.html)，具体策略以上述项目清单为准。

## 10. 企业初始化与空白页防复发

- 创建企业流程：`PROVISIONING -> READY` 或 `FAILED`。同时创建所有者关系、套餐策略、品牌默认值、权限模板和必要工作空间；事务外资源通过 outbox 驱动并幂等重试。
- 权限模板固定版本及摘要，记录每家企业已应用版本。首建使用标准模板，后续走增量迁移，禁止启动时全量覆盖管理员定制权限。
- 预检必须验证菜单根节点、角色、角色菜单/资源绑定、有效所有者和默认组；仅表存在不算完成。失败时不得标记 READY。
- 前端区分企业未初始化、正常但无授权、权限接口故障。显示明确状态、重试、切换企业和退出入口，保护信息不泄露给无资格用户。
- 新建企业的第一位所有者必须实际通过登录 -> 选择 -> 菜单 -> 用户列表测试；这是发布门槛，不是上线后手工补救项。

## 11. 品牌和 Caddy 域名托管

### 11.1 品牌规则

统一入口永远使用 Singu X 平台品牌。企业选择后的品牌来自所选企业与权益快照；免费企业名称可显示，Logo/favicon/主题采用平台默认。收费企业的品牌上传需校验资产归属、类型/大小、安全内容，不允许任意脚本或全局样式注入。降级保留品牌草稿但不继续生效。

### 11.2 域名状态与 HTTPS

主域名明确为 `www.ciyuancenter.cc`；不自动认为拥有根域名或所有子域名控制权。平台分配子域名若未来需要，应为 `{code}.ciyuancenter.cc`，不是 `{code}.www.ciyuancenter.cc`。企业平台域名与现有网页应用项目域名分别管理，但共享冲突注册表。

```text
PENDING_DNS -> OWNERSHIP_VERIFIED -> CERT_PENDING -> ACTIVE
                   |                   |
                   +------ FAILED <----+
ACTIVE -> SUSPENDED / REMOVED
```

1. 后端校验套餐/数量/角色，规范化小写、IDN、尾点与端口规则；全局唯一，拒绝平台保留域名和非法主机名。
2. 为本次绑定生成随机 TXT 验证值，显示 `_singux-verification.<host>` 和解析到平台入口的指引；不要求客户交出 DNS 账号。
3. 异步验证 TXT 所有权和 A/AAAA/CNAME 路由，绑定尝试 ID 防旧挑战重放；设置超时、重试、限流并防内网探测。
4. Caddy 只为已验证且权益有效的候选域名申请证书；证书可用后再开放企业业务路由。所有权 TXT 验证和 ACME 证书挑战是两件事。
5. 首期优先受控发布明确域名配置；发布器验证配置并原子启用，审计回滚。当前 Caddy `admin off` 若改为动态管理，只允许 Unix socket/受控内部管理通道，不能把管理 API 或 Docker socket 暴露给网页后端。
6. 若使用 On-Demand TLS，ask 接口必须可查询 `OWNERSHIP_VERIFIED/CERT_PENDING` 的签证资格，不能要求先 ACTIVE 而造成“有证书才能签证”的循环。业务访问仍独立要求 ACTIVE、有效 membership 和一致 Host。
7. ask 查询不依赖租户业务会话，只接受网关受控入口；未知、过期验证、解绑、套餐不符均拒绝。拒绝签证不等于撤销已缓存证书，业务 Host 校验必须持续有效。
8. 自动续期、证书到期、DNS 漂移和域名解绑有监控；解绑移除路由授权，重新绑定要求新验证。先建立可用替代入口，再删除正在使用的主入口。

Caddy 自动申请/续期需要正确 DNS、可达挑战端口和持久化数据目录，测试先使用 staging，参见 [Caddy Automatic HTTPS](https://caddyserver.com/docs/automatic-https)。按需签证必须限制可签域名，参见 [Caddy On-Demand TLS 配置](https://caddyserver.com/docs/caddyfile/options#on-demand-tls)。这些资料说明的是网关能力，不是本项目已完成的验收。

Caddy 到后端只走私网；清理外来 Forwarded/X-Forwarded-*，后端只信任确定的代理。公共品牌缓存按规范化 Host 隔离；私人会话与企业列表禁用公共缓存。自定义域名首期独立登录，不共享 `.ciyuancenter.cc` 宽域 Cookie，也不在 URL 传访问令牌。

## 12. 套餐、额度与支付预留

- FREE 不能通过配置额度解锁自定义 Logo/域名；这是后端产品约束，不仅是 UI 限制。
- 按已确认需求，首期只要求额度字段、后台调整、状态展示和审计；后续实际计量/强制按指标单独上线。不能把计量设计写成当前已交付的自动扣费，也不能用“额度预留”掩盖仍需完成的数据授权隔离。
- PAID 的具体能力由有效套餐版本和企业覆盖决定；付费标记不等于任何能力无条件开放。所有修改携带原因、版本和生效时间。
- 成员、空间、智能体、存储字节、月模型 token、月请求、并发任务、自定义域名等指标先保留可配置接口，不编造限额。每项必须标出 `UNCONFIGURED/LIMITED/UNLIMITED` 及计量/强制状态。
- 未配置不能解释为不限额；未验收计量的高成本功能在试点范围外不开放。当前政策只有预留字段，前端不能显示“额度已强制执行”。
- 真正执行额度时采用 `reserve -> settle/release`，数据库条件更新/事务或经过验证的原子缓存方案；幂等事件、超时释放、周期边界、并发席位、账实对账均需测试。
- 现有 SYSTEM/AGENT/SKILL 订阅及个人积分不直接改成企业订阅；模型调用、积分和企业配额的扣减顺序须明确，避免重复收费。
- 本期人工分配套餐并记录来源，不产生虚假的已付款订单。微信 `WECHAT_PAY`、支付宝 `ALIPAY` 仅保留约定，状态为 NOT_CONFIGURED，不显示可用付款按钮。
- 支付细节单列 `tenant-payment-reservation.md`，未来经独立商户/验签/幂等/退款验收后接入，不列为本期“完整多租户”必须实现的收款功能。

## 13. 发布、备份和一键更新

本机继续使用独立测试环境和 18090，不向互联网开放数据库。正式发布使用 C 盘前端和 D 盘后端生成固定版本、可追溯摘要的 linux/amd64 镜像，保存代码版本、数据库迁移版本和权限模板版本。

`update.sh` 只负责经审核的 schema 不变且数据向后兼容版本；首次多租户表/索引/会话改造不能标为 image-only 版本。该迁移发布应有预检、停写范围、MySQL/上传/对象存储等恢复点、逐步迁移、对账和回滚方案，不能认为数据库一份 SQL 备份涵盖全部业务数据。

前端静态文件采用版本目录/镜像原子切换，HTML 禁止长期缓存，带内容摘要的 JS/CSS 可长期缓存；保留合理旧资源窗口，避免边构建 dist 边服务造成 chunk 缺失。更新失败不清理数据卷。只在已验证数据兼容时自动回旧镜像，不能自动恢复数据库覆盖新写入。

上线健康门槛不仅是容器 healthy，还要检查：已应用的 schema/权限模板版本、样例账号菜单、登录选择企业、关键资源读写、用户导出，以及 A/B 越权拒绝。日志记录 releaseId/requestId/sessionId 摘要/tenantId，不记录令牌、密码或支付密钥。

| P2 企业生命周期与成员 | 创建/就绪状态、标准权限、邀请/转移/撤销、平台与企业账号管理拆分 | 新企业可直接登录有菜单；非平台用户不能操作其他企业/全局账号 |
| P3 全链路隔离 | 按第 9 节清单补业务、文件、缓存、检索、任务与流式隔离；补切换取消 | A/B 令牌、ID、域名、文件、批量、SSE、任务均无法越权 |
| P4 企业品牌与域名 | 免费限制、品牌资产、TXT、Caddy 配置/签证、续期/解绑/降级 | 仅验证、权益有效且证书就绪的域名能进入对应企业 |
| P5 套餐与运维 | 人工套餐版本、额度配置；按指标逐项计量/强制、用户导出审计、真实更新演练 | 不假报扣减完成；备份可恢复；支付保持未接入 |
| P6 灰度上线 | 内部企业 -> 少量外部企业，监控、告警和回归报告 | 所有开放能力完成隔离验收；未完成的外部能力默认关闭 |

P1 可先在隔离开发环境展示页面，但 P1/P2 完成不等于可对外提供多租户服务。P0/P3 是所有对外企业业务的安全前置；域名与额度可按实际开放能力分批上线。现有两个开关不能只为显示选择页而直接在服务器同时开启。

每阶段同时交付：源码变更、迁移/回滚说明、自动化测试、实际 API/浏览器验证、VERSION_CHANGES 更新。证据包含通过项、失败项和未测试项，不能用“已改代码”代替“已验收”。

## 15. 验收用例与停止上线条件

至少准备 A/B 两个企业、一个仅 A 用户、一个仅 B 用户、一个 A 所有者/B 普通成员的跨企业用户，以及一个不加入企业的平台管理员。

| 测试组 | 必须通过 |
| --- | --- |
| 登录选择 | 未登录看不到成员企业；0/1/多企业状态正确；所有登录方式进入同一流程；无企业平台管理员仍可进入平台管理 |
| 选择安全 | 修改 tenantId 被拒；身份票据不能调业务；票据过期/重放/并发选择均受控 |
| 会话角色 | 同账号 A 所有者权限不能带到 B；移除 B 成员只影响 B；角色变更后的旧刷新凭据同样失效 |
| 界面与刷新 | 首次登录、直接访问选择页、F5、返回、切换账号、断网重试、长企业名、移动端均不白屏 |
| 菜单初始化 | 新建企业实际有正确菜单/资源绑定；初始化失败不能 READY；无权限有提示；权限升级不覆盖定制 |
| 多标签/流 | A 慢请求在切到 B 后返回被丢弃；旧 SSE 不能继续输出；上传和后台任务不会变成 B 资源 |
| 资源隔离 | 单查、列表、统计、批量、导出、分享、向量搜索、附件 URL、API Key、自定义表、外部执行逐项测试 |
| 域名 | 伪造 Forwarded、未知 Host、A 域名/B 会话、TXT 失败、重复域名、证书失败/续期/解绑/降级均正确拒绝或恢复 |
| 免费限制 | 直接请求品牌/域名 API 不能绕过免费限制；付费失效后权益不继续使用缓存生效 |
| 额度/支付 | 未配置与不限额有区别；启用计量的指标并发不超扣；无真实支付入口，不把人工开通标为已付款 |
| 运维 | migration/备份失败立即停止；镜像兼容回滚与数据恢复演练成功；UI 静态资源切换不丢 chunk |

以下任一项存在即禁止对外开放多租户：跨企业资源可读写；权限初始化靠人工补救；身份票据可访问业务；签证允许任意域名；撤销后旧会话/长连接可持续访问；未审核外部执行服务可跨企业取数；无法从备份恢复。

## 16. 本期范围说明

本方案的“完整”是覆盖登录、授权、业务隔离、企业生命周期、品牌域名、额度、发布与验收全链路，不是承诺一次修改就全部上线。下一批建议从 P0/P1 的源码审计和两阶段登录接口开始，同步补空菜单错误状态，再实现企业选择页；不能只在原登录接口前加一个 tenantId 下拉框。

无需再确认的事项：前后端目录、主域名、多企业成员、免费版 Logo/域名限制、Caddy、微信/支付宝只预留。公开部署前仍需确认真实域名/DNS 控制权、证书通知邮箱、试点企业/所有者名单、额度数值/计量周期及维护窗口；这些信息不阻塞本地 P0/P1 开发。
