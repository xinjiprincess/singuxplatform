## 3 系统架构及模块职责

### 3.1 网页前端

采用 React、TypeScript、Umi Max、Ant Design；工作流编辑使用图编辑组件，网页开发编辑器使用 Monaco。Nginx 提供构建后的静态文件并代理后端接口。

主要目录：

- `src/pages`：页面和业务界面。
- `src/components`：共享组件。
- `src/hooks`：会话、文件和开发服务等业务逻辑。
- `src/services`：HTTP 接口封装。
- `src/models`：全局状态。
- `src/utils`：路由、品牌、会话及工具函数。
- `src/locales`：多语言文案。
- `config`、`src/routes`：构建与路由。
- `public/logo`、`src/assets/images`：品牌和业务图片。

主要入口包括 Login、EditAgent、AppDev、SystemManagement、PlatformTenants 和 PlatformPortals。页面是否可见依赖部署版本、功能开关、租户和用户权限。

### 3.2 后端

后端为 Java Maven 多模块项目，根 POM 使用 Spring Boot 3.3.8。具体 JDK 与依赖以当前 POM、Dockerfile 为准，不凭本机全局 Java 版本判断兼容性。

- `app-platform-bootstrap/app-platform-web-bootstrap`：应用启动、鉴权及请求拦截。
- `app-platform-modules/platform-system`：用户、权限、租户、成员、配置和开放 API。
- `app-platform-modules/app-platform-agent`：智能体与编排。
- `app-platform-modules/app-platform-model-proxy`：模型调用代理。
- `app-platform-modules/app-platform-custom-page`：网页应用及代理相关能力。
- `sql/migrations`：增量数据库迁移，不能对生产无差别执行所有脚本。

### 3.3 基础设施

当前 Compose 包含 frontend、backend、MySQL、Redis、etcd、MinIO、Milvus 和 Elasticsearch。MySQL 保存业务数据，Redis 提供缓存及权限相关状态，MinIO 保存对象，Milvus 支撑向量数据，Elasticsearch 支撑搜索，etcd 为相关服务提供元数据能力。

MCP 代理、文件服务、RCoder 和动态执行容器是配套运行链路，不因为主 Compose 正常就自动具备。

请求主链路是：浏览器或客户端 → HTTPS 网关 → 前端代理/业务 API → 后端权限与业务服务 → 数据库或模型/工具服务。沙箱执行链路需另行接通调度、文件和预览代理。

## 4 智能体、模型与工作流运行

### 4.1 一次调用

1. 用户提交对话或工作流试运行，后端验证身份和资源访问范围。
2. 智能体组合系统提示词、历史消息、用户输入、附件和工具定义。
3. 工作流 LLM 节点构造模型上下文，经 `ModelInvoker` 调用模型客户端。
4. `ModelClientFactory` 按协议和权重选择上游配置，通过内部模型代理凭证调用上游。
5. 上游返回正文、推理、工具调用或用量；工具执行结果可能进入下一轮模型调用。
6. 对话事件通过 SSE 返回前端，工作流同时记录节点输入、输出、状态和时间。

智能体不是大模型本身：模型负责生成，智能体负责上下文和工具组织，工作流负责节点和变量编排。

### 4.2 配置原则

模型 URL 必须是完整 HTTP(S) 地址，包含实际端口和供应商要求的路径。不要只填 IP，不要擅自把所有供应商地址统一截断为 `/v1`。

内部模型代理地址与公开站点地址分开；本地修复使用 `model-api-proxy.internal-base-url`，同进程缺省指向 `http://127.0.0.1:18086`。拆分容器时 localhost 指向当前容器，必须改为可达服务地址。

“成功”“有 Token 数”与“有最终正文”不是同一件事。诊断须同时核对 requestId、正文、reasoning、tool calls、finish reason、响应类型和时间字段。

### 4.3 资源与追踪

模型和工具调用都要维持用户、租户、空间与追踪上下文；跨线程任务不能仅依赖线程局部变量。文件、知识库、搜索、分享和异步任务要单独验收隔离。Token 估算或 usage 记录不代表企业计费已经实现。

详细代码链路见 [智能体与模型运行设计](agent-model-runtime.md)。

## 5 用户、鉴权与开放 API

### 5.1 凭据分类

网页登录凭据、网页会话令牌、平台开放 API Key、模型供应商 Key、SSH 凭据是不同身份材料，不能混用。文档和发布包不保存真实密码、Key 或 token。

平台 API 使用 `Authorization: Bearer <平台APIKey>`。Key 所属账号为管理员不意味着自动拥有全部开放接口；仍可能受到 Key 范围、角色/用户组授权、账号状态、租户上下文和限流控制。

### 5.2 导入使用的接口

- `POST /api/v1/system/user/list`：分页读取并核对现有账号。
- `POST /api/v1/system/user/add`：新增普通用户。
- 多租户模式的成员接口属于独立能力；当前生产单租户导入不调用它。

客户端列表请求形状为 `{pageNo, pageSize, queryFilter:{}}`，成功业务码预期为字符串 `0000`。记录 ID 必须可安全表示；不接受已失真的大整数。

新增请求只使用普通用户角色 `User`，不是批量创建管理员。0.1.6 可按显式确认的任务策略更新匹配的普通账号并重置密码；不更新管理员，不默默改变历史任务。

## 6 多企业租户与申请审核

本节描述本地实现和设计边界，不要求当前生产启用。

用户为全局身份，可加入多个企业；成员关系保存角色和状态。平台管理员、企业 OWNER、企业 ADMIN、企业 MEMBER 的权限范围不同，前端菜单隐藏不是后端授权。

登录流程为账号认证 → 短期身份票据 → 首次公司/学校资料 → 选择有效企业 → 企业会话。切换企业重新签发会话；成员角色版本变化后旧会话须拒绝使用。

首次资料支持公司/学校名称。当前相近企业搜索为至少两个字符的名称子串查询，最多十项，不是语义模糊匹配。用户申请创建或加入企业时填写联系人、联系方式和说明；平台审核通过后才创建 OWNER/MEMBER 关系，不能靠提交申请直接取得权限。

相关开关包括 `PLATFORM_TENANT_POLICY_ENABLED`、`PLATFORM_MEMBERSHIP_ENABLED`，不能直接在旧生产上打开。启用前核对 migration、管理员白名单、历史账号、默认租户、重复身份和回滚兼容。

免费版禁止自定义 Logo/域名，额度由管理端配置。配置可保存不等于每项业务已经原子扣减。自定义企业域名与网页应用项目域名分开管理。

Caddy 是自定义域名自动 HTTPS 的选定方向；域名所有权验证、唯一性、受信任 Host、证书签发和续期必须完整验收。不能把现有网站 HTTPS 等同于任意租户域名已受支持。

完整隔离还须覆盖数据库查询、对象存储、Redis、向量/搜索、SSE、分享下载、后台任务和执行容器。当前不能宣称全部完成。

## 7 比赛专用入口及品牌背景

本地记录入口为 `http://127.0.0.1:18093/zhichuangbei/login`，官网流程为同端口 `/login`，管理路径为 `/platform/portals`。端口为历史本地部署记录，本次整理未确认容器仍运行。

专用入口绑定固定租户，登录不展示企业选择。支持名称、副标题、Logo/favicon 路径、主题色、启停和时间窗口；入口创建后不能直接改绑租户。停用、未知或过期入口不回退到其他品牌。

官网和比赛可分别配置登录页及工作台背景。当前实现接收站内图片路径并预览，不等于内置任意文件上传。背景必须可公开访问，不使用私有文件或短期签名 URL。

建议使用经确认可公开的持久化品牌目录，前端只读挂载。改图使用新文件名，避免缓存；不要把图片直接写入运行容器后当作永久配置。

同域不同路径共享 origin，不是浏览器安全隔离。不可信网页应用预览应放在独立 origin。比赛租户不自动复制官网资源，也不自动加入全部官网用户。

## 8 MCP、沙箱与网页应用

MCP 负责工具协议和调用，mcp-proxy 为相关工具提供运行/代理服务。NPX 工具还依赖 Node/npm、网络与依赖版本；卡片一直“部署中”不意味着工具已经启动。

已有历史排查记录：生产代理地址指向 `host.docker.internal:8020`，而服务器缺少对应监听和代理容器。本地完成过代理健康、14 个文件工具列表及只读调用测试，以及部署失败状态回写测试。这不是生产所有 MCP 工具已恢复的证明。

RCoder 提供沙箱调度和执行器相关能力；文件服务管理项目内容。网页应用完整流程包括创建项目、文件写入、模型生成、SSE 进度、开发服务器、预览/WebSocket、发布和回收，必须逐段验收。

不要把所有相关 Git 仓库都无条件变成常驻容器。模板、构建插件、脚本注入、引擎依赖与网络穿透组件的角色不同，应依据调用链决定如何构建和运行。

调度器如果持有 Docker socket，具有高权限基础设施能力，应与普通业务和不可信工具隔离。必须限制 CPU、内存、进程、运行时间、网络和宿主路径，并验证停止回收和文件持久化。

## 9 本地用户导入客户端

### 9.1 定位与启动

独立 Windows x64 Electron 客户端，React/Ant Design 界面；不依赖本机 Docker 才能启动，但导入需连接平台 API。不是通用桌面智能体客户端，也没有内嵌 SSH 管理。

当前程序：`C:\Users\zhang\nuwax\tools\user-manager\release\0.1.6\SinguX-User-Manager-win32-x64\SinguX-User-Manager.exe`。

退出旧版再启动新版。旧版本保留，同一用户配置不应同时开启多个实例。发布目录不是仅一个 EXE，搬到其他机器时需保留整个目录的依赖文件。

本机配置位于 Windows 用户数据目录，使用 Electron safeStorage 加密；加密文件不能作为跨机器通用配置包。真实 Key 不在源码或发布包中。

### 9.2 正常操作

1. 在环境配置选择官网 HTTPS 地址及单租户模式。
2. 在 API Key 管理中配置平台 Key，选择正确环境。模型 Key 只用于可选字段识别。0.1.6 更新还需要用户更新和详情接口授权，当前生产已具备；本轮未实际更新生产用户。
3. 填写学校代号，例如 `cdut`；添加表格或选择目录，可递归扫描。
4. 核对列映射、手机号和邮箱等规则，生成预览；检查错误、重复和来源行。
5. 点击检查连接，再执行导入所选或一键全部导入。全部导入不受当前页或勾选行限制，只提交校验合格项。
6. 在任务中心查看结果，按需暂停、单独核对错误项，导出账号密码表或未成功账号表。

### 9.3 账号密码规则

当前默认用户名和初始密码均为学校代号直接拼接学号/工号。例如两者都为 `cdut000123`，不包含加号或空格。学号前导零按文本保留。

不再依赖旧后端支持纯数字用户名。学校代号和规则按批次保存，旧任务不自动改写；更换规则必须重新生成预览和新任务。

0.1.6 新任务默认启用更新已有普通账号并重置密码，可关闭。旧 UID 匹配需姓名及联系方式佐证，多重匹配、管理员、停用和确认后变化会拦截；不修改原 UID。学校代号加学号仍容易猜测，应通知用户尽快改密；导入工具不证明服务端已经强制首次改密。

### 9.4 文件和 AI 范围

支持 xls、xlsx、csv、目录扫描、报名模板解析和普通表格列映射，不是任意 PDF/图片 OCR 工具。

解析工作线程拒绝单文件超过 10 MB、过大或加密压缩表格；当前检查包含单表一万行/80 列边界。超限应按错误提示拆表，不通过取消校验绕过。

AI 字段建议只在用户确认后发送字段名，不发送整份名单、密码或人员数据；仅推断映射，不决定权限，也不能替代人工校验。

### 9.5 速度与错误处理

新任务默认 3 路并发，可配置 1 至 5 路；全局启动间隔最小 250ms，理论最高约 240 条/分钟，实际受接口响应、保存开销和服务端限流影响。成员关系处理及历史未知状态有串行核对路径。

单个字段错误、身份冲突或新增响应不确定不再阻断其余账号。认证失效、限流、列表预检失败及本机持久化故障仍暂停整批。

未知状态表示可能已写入但没有可信响应，不等于确认失败。恢复先查询，查不到也不盲目重发；需到平台核对。不能通过删除历史来规避重复提交保护。

任务中心“核对该账号”只处理目标错误项；不强制合并冲突。已启用更新的任务按确认的目标和规则执行，不启用时不覆盖已有用户。“重新核对失败项”会重新读取服务器数据；错误字段需要在原表修正后生成新的预览。

当前客户端对现有用户列表有一万条保护上限，不能将并发提升理解为已经支持任意规模全校名单。超过范围需要后续设计服务端按标识查询、稳定分页或异步导入任务。

### 9.6 导出

账号密码 Excel：提供本次已确认创建或更新账号的初始密码；未修改的已有账号和结果未知账号不伪造密码。

未成功账号 Excel：导出当前快照，排除 done/updated/existing，包含失败、冲突、待核对、尚未提交及成员关系未完成项；字段包括姓名、账号、学工号、学校代号、联系方式、状态、错误、用户 ID、建议和来源。不含密码。

结果报告：CSV，包含账号、来源和错误，便于核对。任务中途导出可能包含尚未提交项；最终结果应在批次结束后重新导出。

### 9.7 代码入口

- `desktop/main.cjs`：IPC、配置、文件选择、任务和导出。
- `desktop/preload.cjs`：受限 IPC 白名单。
- `desktop/core.cjs`：映射、规范化、校验与去重。
- `desktop/parse-worker.cjs`：表格解析和文件限制。
- `desktop/api.cjs`：平台调用、身份匹配、错误分类。
- `desktop/queue.cjs`：并发、节流、持久化和未知写入保护。
- `desktop/account-report.cjs`：密码表与未成功表导出。
- `desktop/store.cjs`：本机加密持久化。
- `src/main.tsx`、`src/DataTable.tsx`：界面、列表和分页。

## 11 Docker 部署、更新和回滚

### 11.1 发布前盘点

```sh
docker compose version
docker ps --format 'table {{.Names}}\t{{.Image}}\t{{.Status}}'
docker inspect singux-backend-1 --format '{{.Config.Image}} {{.Image}}'
docker inspect singux-backend-1 --format '{{index .Config.Labels "com.docker.compose.project.working_dir"}} {{index .Config.Labels "com.docker.compose.project.config_files"}}'
df -h
```

以上为只读示例。不要公开完整环境变量、完整 inspect 输出或 `.env`。记录实际 Compose 文件、项目名、端口、镜像 digest 和挂载，不用历史目录猜测。

### 11.2 本地与生产分开

根 Compose 是开发/部署参考，不能直接用它覆盖已运行的生产配置。当前本地后端包含多租户开发，旧单租户修复需基于线上兼容基线移植最小改动。

新版本应先在隔离数据库验证登录、开放 API、智能体、文件和回滚。多租户/比赛迁移不能夹带进普通单租户更新。

### 11.3 备份与持久化

备份数据库、MinIO/上传数据、Compose 和私密环境配置、品牌资源、旧镜像标签与 digest。数据库与对象引用应尽量保持一致时间点，必须做恢复演练。

迁移 Docker 存储到 `/data` 前先确认挂载和开机持久化，停写并备份；Docker 与 containerd 的路径须一起核对。不要把对话中的历史迁移片段直接重复执行，也不要删除旧目录直到校验完成。

### 11.4 镜像更新

推荐不可变、唯一版本镜像。仓库 pull 复用镜像层，离线 save 包不是二进制差分。不要向运行容器随意覆盖 JAR/dist 并将其称为可回滚更新。

仅在镜像已加载、配置已审核、备份与兼容性验证完成后，使用实际生产 Compose 对目标服务执行 `up -d --no-deps` 类定向更新；参数以现有部署脚本和 Compose 版本为准。不要运行 `down -v` 或重新执行初始化脚本。

更换镜像不会回滚期间新增的数据；数据库恢复也可能覆盖新数据，必须另行评估。客户端 EXE 更新不改变服务器镜像。

### 11.5 在线更新边界

现有 `deploy/offline/update.sh`、`update-online.sh` 提供更新基础；在线入口要求 HTTPS 清单及可信来源校验值，不执行下载来的任意 shell。生产发布渠道、签名、防降级、管理界面和演练尚不能视为完成。

用户当前范围不要求上线真实支付或在线发布。本次文档整理不修改服务器。

## 12 排错手册

### API 不存在或无权限

先核对 HTTPS 域名、请求路径、Key 类型和状态；再查接口定义与角色/用户组开放 API 授权。管理员身份本身不够。只读 list 成功不代表 add 已实测，不能用新增真实账号作无授权探针。

### 用户名不能为纯数字

当前客户端填写学校代号，使用 `cdut` 加学号。重新生成预览，不继续历史纯数字账号任务。客户端更新不代表后端纯数字补丁已发布。

### 联系方式或登录名已存在

看冲突详情中的用户 ID、UID、登录名、手机号和邮箱差异。先确认是否为同一人、旧账号或表格错误，不强制合并。导出未成功账号后人工核对；已存在账号的密码不由客户端推测。

### 导入慢或停住

先看批次是否为旧串行任务、全局间隔、并发数、接口耗时和限流。学校代号错误不能通过提高并发解决。暂停后等待在途请求返回，不强行重启反复导入。

### Failed to json 或模型输出 null

收集 requestId 和发起时间；查真实 HTTP/SSE 响应、代理路由、正文及工具调用，排除空帧、业务错误 JSON、错误模型参数和无最终正文。不能只看耗时或 Token。

### URI with undefined scheme

检查供应商 URL 是否带协议；再核对后端内部代理地址，避免相对路径或容器内不可达地址。不要把模型密钥放在 URL 中。

### Connection refused 与 host.docker.internal

检查目标服务是否存在、监听端口是否正确及容器网络是否可达。Windows 本机能访问不代表 Linux 服务器上同样成立。网页创建依赖文件服务和调度器，不是只启动前后端就足够。

### MCP 一直部署中

查代理可达性、工具依赖安装、握手及后端状态回写。对单个已审核工具重试，不直接改数据库为 Deployed，也不批量运行未知 NPX 包。

### 移动端或桌面壳白屏

核对主 HTML、JS/CSS、浏览器控制台、API 和缓存。历史生产曾因 `/m/` 未部署却按 UA 跳转导致失败；已有入口补丁不等于完整移动站已交付。

### 文件上传失败

区分上传请求失败和解析节点不支持格式。图片上传成功不代表“文档提取”能读取图片，需要匹配 OCR/视觉能力；同时检查文件大小、鉴权、存储和节点输入类型。

## 13 安全和数据保护

不在文档、日志、截图、源码或制品中保存真实密码和 Key。历史在聊天中提供过的凭据建议轮换，通过受控渠道交付；不要把 SSH root 密码填入客户端。

用户名单和未成功报告也含个人信息，按最小权限保管；密码表只在必要时导出并受控发放，不上传到模型或公开群聊。客户端 AI 只识别表头。

保留 API 最小授权、限流和未知请求保护，不为导入方便关闭鉴权或自动授予管理员。真实服务端权限边界需要负向测试。

许可证需按每个实际仓库和依赖核对：当前前端 package 标注 Apache-2.0，本地客户端 package 标注 UNLICENSED。不能仅凭此前“项目是 MIT”的描述推断所有模块许可证，也不要把界面品牌清理与删除 LICENSE/NOTICE 混为一谈。正式分发前另做许可证清单审核。
