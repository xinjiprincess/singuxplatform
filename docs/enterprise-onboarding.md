# 首次登录与企业申请审核

更新：2026-09-28。

## 用户流程

账号验证 → 身份票据 → 公司/学校资料 → 选择已加入企业 → 企业会话。

首次填写单位类型和名称。输入至少两个字符后查询相近企业，最多返回十条名称与 ID，不返回成员或联系方式。当前实现为名称子串匹配，不是拼音、纠错或语义搜索。

用户可以申请加入搜索结果中的企业，也可以填写新名称申请创建企业。申请必须包含联系人、联系电话或邮箱、申请说明；同一个账号最多一条待审申请。待审或被驳回都不会获得企业权限，页面显示审核状态和原因。

## 管理员流程

平台管理的租户页面新增“企业审核”，查看申请、联系方式、说明，填写审核意见后通过或驳回。普通企业管理员不能调用平台审核接口；申请人不能审核自己的申请。

通过创建申请：事务内创建企业并登记申请人为 OWNER。通过加入申请：验证企业启用、账号有效、没有旧成员关系，再创建 MEMBER。已有成员被撤销后不能通过申请绕过撤销，需管理员处理原成员关系。

审批使用申请行锁和待审状态条件更新，重复审核不会重复创建。驳回不创建租户或成员。保存审核人、时间、结果、意见和目标租户，后续审计不得覆盖这些已完成记录。

## 数据与接口

迁移文件：后端 `sql/migrations/20260928-tenant-onboarding.sql`。

- `tenant_onboarding_profile`：全局账号的单位资料，不是授权数据。
- `tenant_application`：申请快照及不可重复处理的审核结果。
- `GET/PUT /api/me/onboarding`：能力开关和本人资料。
- `GET /api/me/enterprise-search?query=...`：受限身份可用的企业名称查询。
- `GET/POST /api/me/enterprise-applications`：本人申请查询、提交。
- `GET /api/platform/enterprise-applications?before=...`：平台审核列表，每批最多 50 条。
- `POST /api/platform/enterprise-applications/{id}/review`：平台审核。

所有本人接口从认证上下文取得 userId，不接受客户端指定申请人。身份阶段仅精确放行上述本人接口、企业选择和注销；不能访问审核和业务接口。Cookie 写请求仍需同源检查。

## 上线顺序

1. 备份数据库并执行新增表迁移，不修改或删除旧账号、租户和业务表。
2. 部署包含新接口的后端及对应前端。
3. 在独立测试环境启用 `platform.tenant-policy-enabled`、`platform.membership-enabled`、`platform.onboarding-enabled`（环境变量分别为 `PLATFORM_TENANT_POLICY_ENABLED`、`PLATFORM_MEMBERSHIP_ENABLED`、`PLATFORM_ONBOARDING_ENABLED`）。三个开关需要同时开启。
4. 验证新老用户资料、无企业用户申请、创建与加入审批、拒绝后重申、普通管理员越权、自审、重复审批、撤销成员、禁用企业。
5. 通过隔离与初始化验收后再启用生产。默认关闭 onboarding，避免旧客户端突然被资料校验阻断。

当前首次资料保存成功后不重复强制填写。加入或创建获批后，用户刷新企业列表或重新登录再选择企业。短期身份票据过期需重新登录，已经提交的资料和申请保存在数据库。

## 发布限制

此次创建企业采用共享入口，不自动绑定自定义域名、签证书或复制管理员密钥。企业默认免费策略；配额仍遵循现有实现边界。数据库事务仅覆盖数据库操作，不包含外部生态市场注册。生态市场开通、模型配置及工具配置须另行配置和验收。

名称搜索可能暴露企业名称，因此只向已认证账号提供有限结果。若部署包含保密客户，应增加“允许被搜索”开关和邀请机制后再向外部账号开放。生产开放注册前还需配置速率限制及反滥用措施。
