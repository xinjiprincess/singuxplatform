## 目标

每家企业是独立租户，拥有独立资源、成员权限和套餐；用户是全局身份，可以加入多个企业，在不同企业拥有不同角色。平台运营方管理所有租户，企业管理员只管理本企业。

已确认：统一入口为 `https://www.ciyuancenter.cc`；免费版禁止自定义 Logo 和自定义域名；额度预留并由平台管理端配置，不在前端写死数值。保留现有账号与数据，优先复用已有默认租户 ID，不盲目新建租户或重写全部 tenantId。

设计默认（非用户已确认事项）：免费版 favicon、登录素材及品牌主题也使用平台默认，企业内部名称可修改；首期由运营创建企业、手动分配套餐，在线支付后置。

## 租户识别和登录

1. `www.ciyuancenter.cc` 是统一平台入口，不固定映射某家企业。登录前显示平台品牌；认证后查询当前用户的有效成员资格，一个企业可自动选择，多个企业显示切换器，无企业则显示邀请/加入状态，不自动加入默认企业。
2. 免费企业共用统一域名。工作区建议 `/t/{tenantCode}/...`，最终路径按现有 Umi 路由核对；code 只是导航参数，不是授权依据。平台管理先放 `/platform/...`，使用独立平台权限。平台分配的 `{code}.ciyuancenter.cc` 子域名后续可选，不生成 `{code}.www.ciyuancenter.cc`，不作为首期依赖。
3. 认证后的身份会话只用于成员查询、企业选择，不得访问租户业务。选择企业后校验 tenant/membership 状态并签发绑定 userId、tenantId、membershipId、会话版本和受众的租户令牌。旧 UserInfo.tenantId 兼容为当前企业，而非唯一归属。
4. 付费自定义域名按可信 Host 查找已验证且权益有效的企业；认证后仍验证成员资格。A 企业域名配 B 企业令牌必须拒绝。客户端 tenantId、资源 ID、URL code 均不能代替授权。
5. 公开配置区分 platform/tenant 模式，只返回白名单品牌及必要登录参数。未知、未验证、停用域名返回明确错误，不能回退到旧缓存或默认企业。密钥和支付内部配置另用已认证管理接口。
6. 企业切换重新签发会话；注销、成员移除、企业停用须使对应会话失效。首期一个标签页只有一个活动企业；同源多标签页通过广播同步切换或要求重新选择，禁止旧页面静默使用新企业 token。
7. 切换时取消 SSE/WebSocket、上传、轮询和预览请求，清理用户、权限、空间、会话列表、品牌和主题；对晚到响应按上下文代次丢弃。缓存按 host + tenantId + userId（适用时）隔离，不把改 localStorage key 当作完整隔离。
8. 首期自定义域名独立登录，不跨域共享宽域 Cookie，不在 URL 传访问令牌。后续统一登录采用短时一次性、绑定目标域名的换票机制；redirect 使用允许列表。
9. 边缘网关校验域名并清理外来转发头，后端只信任明确代理。Host 规范化集中处理，CDN 缓存按 Host 隔离；健康检查使用内部专用入口，不绕过业务鉴权。

以上为逻辑模型，不是直接新建表清单；先盘点已有表再确定扩展或复用。所有者可由 membership 表达，与 owner_user_id 的一致性通过事务保证。

- MySQL：空间、智能体、工作流、插件、技能、知识库、文件、页面应用、聊天、API Key、模型凭据、积分和订单逐表核对；关联、批量、导出、自定义 SQL 同样校验租户。唯一约束按业务加入租户维度，共享广场资源明确公开策略。
- Redis：会话、锁、幂等键、限流、缓存区分租户；全局身份验证码与租户业务键分开。
- 文件：当前 Compose 默认使用本地 `/data/uploads`，不能假设所有文件均在 MinIO。本地与对象存储都需租户命名空间、归属校验、鉴权下载或短时签名 URL。
- Elasticsearch/Milvus：写入、查询、聚合、删除、向量检索强制租户条件；缺少上下文即拒绝。
- SSE、异步任务、外部执行/构建/日志/Agent 服务必须显式传递并验证上下文，线程池使用后清理。现有 Compose 引用了外部服务，它们不会自动获得隔离能力；未验证前保持相关多租户功能关闭。

## 域名托管

企业添加域名后，平台生成 TXT 所有权验证值及 CNAME/A 解析指引；验证通过后激活路由并签发 HTTPS 证书。网关按 Host 映射租户，自动续证。限制重复域名、未验证域名、可绑定数量和解绑正在使用的主入口。企业平台域名与现有「网页应用项目域名」分开管理。

实施时顺序为申请 -> TXT 验证 -> 解析检查 -> 证书就绪 -> 激活登录，不能证书尚未就绪就开放入口。免费企业在后端拒绝创建/验证/激活自定义域名；检查与页面应用域名的全局冲突。验证任务防内网地址访问并限流，巡检 DNS 失效、域名易主、续证和套餐到期。

部署先保障统一域名 HTTPS。双层代理下，内层 Nginx 不能以自身 HTTP scheme 覆盖边缘 HTTPS 协议信息，且只能采纳可信上游。数据库/后端不直接暴露公网。数据盘迁移与多租户发布分开验收；此前迁移是否完成本次未验证，上线前检查自动挂载及备份恢复。

## 免费版和付费版

企业套餐与现有 SYSTEM/AGENT/SKILL 订阅归属分离，不能把个人订阅和积分直接迁成企业账单。复用已有组件及可复用支付能力前，先核对后端归属模型。

| 能力 | 免费版 | 付费版 |
| --- | --- | --- |
| 多企业成员及企业切换 | 支持，受各企业成员额度约束 | 支持 |
| 企业内部显示名称 | 可改，不替换平台公共入口品牌 | 可改 |
| 自定义 Logo | 禁止 | 按套餐开放 |
| 自定义域名 | 禁止 | 按套餐开放并限制数量 |
| favicon、登录素材、品牌主题 | 平台默认（设计默认值） | 按品牌权益开放 |
| 成员、空间、存储、调用额度 | 平台后台配置，数值待定 | 平台后台配置，数值待定 |
| SSO、审计保留期 | 首期不承诺 | 后续能力，不列为首期必交付 |

免费版 Logo/域名禁用是产品硬约束，不能通过单企业额度覆盖解锁。平台运营可调额度，企业管理员只能查看自己的权益和用量。

额度预留 metric、unit、period、limit、enforcement、effectiveAt、version；候选指标为 members、spaces、agents、storage_bytes、monthly_model_tokens、monthly_requests、concurrent_jobs、custom_domains。按实际计量口径确认，避免与积分重复收费。

1. `0` 表示禁止，`null` 表示未配置，显式 unlimited 表示不限额；旧 callLimitCount=-1 在兼容层转换。未配置不等于不限额。
2. 支持未启用、仅统计、强制限制状态；设计阶段不填虚构数值。生产开放前每项明确限额或显式不限额，未配置的高成本能力默认关闭。
3. 优先级为产品硬约束 > 有效企业额度覆盖 > 套餐版本。配置修改必须有生效时间、原因、审计和缓存失效；发布新版本或显式覆盖，不静默改写已售套餐。
4. 成员按有效 membership 计数，邀请接受与席位占用原子化。消耗任务先预留、完成结算、失败释放；并发原子扣减、幂等事件去重、超时预留补偿。套餐变更不自动清零当期用量。
5. 到期/降级不删数据，超额度限制新增；保留品牌草稿但展示恢复平台默认。自定义域名停止工作区访问，只可固定跳转统一入口重新认证，不再签发该域名会话。
6. 用户已确认：首期仅预留微信支付和支付宝，暂不实现真实支付。现有人工套餐配置不代表收款成功。预留边界见 `tenant-payment-reservation.md`；后续回调必须验签、校验金额/币种/企业订单归属、幂等开通，并覆盖退款、续费与降级。

## 接口草案

- `GET /api/public/tenant/resolve`：按可信域名返回 platform/tenant 模式与公开 DTO；旧 `/api/tenant/config` 保留兼容但不混入管理密钥。
- 兼容现有 passwordLogin/codeLogin；`GET /api/me/tenants` 查询本人的企业；`POST /api/session/tenant/switch` 验证资格并签发租户会话。
- `GET/POST /api/platform/tenants`、`PATCH /api/platform/tenants/{id}`：独立平台权限保护。
- `GET/PATCH /api/tenant/profile`、`PUT /api/tenant/brand`：企业资料和品牌。
- `GET/POST/DELETE /api/tenant/members`：企业成员与角色。
- `/api/tenant/invitations`：受控邀请/接受/撤销；所有权转移为独立事务操作。
- `GET/POST/DELETE /api/tenant/domains`、`POST /api/tenant/domains/{id}/verify`：域名托管。
- `GET /api/tenant/entitlements`、`GET /api/tenant/usage`：权益和用量。
- `GET /api/public/plans`、`POST /api/tenant/subscription/orders`、`GET /api/tenant/subscription`：版本与订购。
- `/api/platform/plans`、`/api/platform/tenants/{id}/quota-overrides`：平台发布版本、人工套餐分配及额度覆盖。

以上为草案，按后端现有 POST 风格及响应封装兼容，不要求全库重写 REST。定义稳定的无资格、租户停用、域名不匹配、权益不足、额度耗尽错误码。

## 实施计划与验收

1. **阶段 0，后端盘点**：找到后端并对齐线上版本，输出实际表/API/权限矩阵，核对 JWT、支付和外部执行服务；确认默认租户、运营超管名单、账号冲突及备份恢复。未完成不得启动数据迁移。
2. **阶段 1，成员与隔离**：增量回填 membership、独立平台权限、租户会话及全链路隔离。验收同账号在 A/B 的角色独立，替换资源 ID/Host/tenantId、批量和导出均不能越权，成员撤销使旧会话失效。
3. **阶段 2，统一入口与管理**：企业选择/切换、缓存及旧流清理、平台企业管理、企业设置、公开 DTO。验收多标签页不串企业，晚到响应不污染，无敏感公开字段，免费版伪造 Logo/域名写入被后端拒绝。
4. **阶段 3，套餐额度 MVP**：人工分配、版本、额度覆盖、统计、预留/结算/补偿。验收后台调整可审计且按时生效，席位/调用并发不超配，重试不重复扣减，未配置状态清楚。
5. **阶段 4，付费品牌域名**：品牌资产归属、TXT、证书续期、跨域登录和降级。验收仅验证且权益有效的域名可访问，A 域名/B 令牌拒绝，免费/降级恢复平台品牌，保留统一入口。
6. **阶段 5，在线支付（本期不实现）**：预留微信支付和支付宝渠道约定，不开放收款。未来另行实现企业订单、回调、退款、续费及降级，验收重复回调只开通一次，归属金额验签正确，旧个人订阅与企业数据保留。
7. **阶段 6，灰度**：内部企业后再外部企业，监控越权拒绝、登录、额度、证书；未审计的外部执行能力不开放。完成恢复与回滚演练。

迁移先增字段/表、回填、对账、切换读路径，最后收紧约束。遇到已有多租户数据不得全部改为默认企业；重复邮箱/用户名人工确认，不自动合并凭据或财务记录。旧 Admin 默认映射原企业管理员，指定账号才授予平台权限。

回滚保留旧字段、映射和快照；产生多租户新写入后不能直接降回无隔离旧版本。需停写核对，并使用兼容新隔离模型的回滚版本，避免回滚泄露数据。自动化测试覆盖 SQL/向量检索/文件/SSE/分享/API Key/异步任务、默认企业回归及免费权益绕过；UI 隐藏和容器 healthy 不构成隔离验收。
